# Game Development Router

Identify the actual project, engine, pinned version, platform, input and existing art contract. A request to configure global skills is not a request to launch an engine. When project identity is unknown, inspect the available context before choosing; do not default to another engine or impose OCC rules on unrelated projects.

Choose the smallest useful set of installed skills. Skills are siblings in `C:/Users/FNHF/.codex/skills`; use the current catalog for bundled plugins. Do not load a whole pack. Continue from valid session context and authorization.

| Outcome | Route |
|---|---|
| Unity editing/build/run | `unity:unity-cli` first; `funplay-unity-dev` for permitted gaps; relevant `unity-*` concept skill |
| UI planning/Pixso | `game-interface-planning`, `game-ui-design`; available Pixso editing skill |
| Game UI implementation | `game-ui-ux` and engine UI skill; `game-ui-design` for state/input behavior |
| Web UI aesthetics | `impeccable` or `ui-design-crafter`; `ui-ux-pro-max` when palette/typography search adds value |
| Pixel art contract | `pixel-art-specification`; then project art direction and `pixel-asset-pipeline` |
| Characters/assets | `create-game-assets`, `game-character-design`, `game-sprite-design` or 3D asset/model skill |
| Visual polish | `game-visual-polish`, relevant `game-feel`, `camera-systems`, `shader-programming` |
| Text/plot | `game-text-style`, `game-story-flow`, `dialogue-systems` |
| Audio | `audio-design`, `game-sound-design`, `game-music-soundtrack-design` |
| Design/content | Relevant genre skill, `level-design`, `game-content-design`; OCC-specific skills only for OCC |
| Three.js major work | `threejs-game-director` plus only needed specialist skills |
| Failure/review | `systematic-debugging`, `bug-reproduction`, targeted engine test or `game-playtesting-usability` |

Community engine-version baselines are references, not migration instructions. Use native host image generation for actual raster generation/editing by default. Provider-specific 3D/audio/image scripts require the selected service and real credentials; preserve existing jobs on unknown outcomes. Installation does not authorize charges, publishing, external messages or model changes. A known unavailable provider blocks only its dependent work.

Build one representative playable scene before expanding a redesigned visual system. Reuse established project contracts. A local UI fix does not require a new design bible, full playtest or whole-project audit. Report delivered changes, proportionate evidence and material gaps.
