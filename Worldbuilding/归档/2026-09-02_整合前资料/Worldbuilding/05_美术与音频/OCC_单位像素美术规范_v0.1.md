# OCC 单位像素美术规范 v0.1

> 动画补充：OCC 全项目所有 64×64 战棋单位执行《OCC_人物双状态帧临时动画规范 v0.1》，不区分模式、地区、阵营或人物／役兽／构造体。单位待机图仍是身份锚点；每项动作只增加 frame_00／frame_05 两个独立正式状态，不要求中间补帧，且不得用平移、拉伸、换色或脚本矩形部件冒充状态变化。

**状态：ACTIVE / SUBORDINATE（2026-08-23）。** 本规范约束剧情模式与肉鸽模式共用的战斗单位静帧原料、规范化输出和后续独立动画帧；它是角色三层视觉中的 A 层（战棋形象），只能细化《OCC 美术规范 v0.1》的唯一全局合同，不得保留不同的尺寸、比例、来源或风格口径。

## 1. 交付边界

- 正式单位首先只交付一张独立 `64×64` 静帧。待机、受击等运行时表现优先使用整数像素位移、色彩/亮度脉冲，不得用同一张图伪造动画。
- 每张原料必须独立生成或绘制；禁止从 AI 拼板、角色海报、地图或其他项目资产中裁切。
- 禁止通过本地生图工作台、localhost 生图 API 或私有 relay 生产单位原料；只使用全局美术规范批准的直接生成渠道或 PixelOver／Aseprite 人工制作。直接渠道失败时停止并记录，不自动切换服务。
- Codex 生成图只作为原料：保留原图、去背中间文件、规范化 PNG、4× QA、调色板、应用接触与 JSON 报告。机器与人工审美通过后只可标为 `FORMAL_CANDIDATE`；Unity 导入另行评审并完成后才是 `FORMAL`。
- 规格正确不能代替美术质量。轮廓、身份、材质、比例、视角和质朴西幻魔法侧风格任一失败均须退回；需要 PixelOver／Aseprite 手工清理时不得以生成图机械 PASS 省略。

## 2. 固定画布与锚点

| 项目 | 规范 | 验收容差 |
| --- | --- | --- |
| 画布 | RGBA `64×64`，单单位、完整可见 | 不允许裁边或多角色 |
| 中心线 | 单位重心围绕 `X=32` | 主体视觉重心在 `X=29–35`；持枪/盾牌可越出但不得失衡 |
| 脚底基线 | 站立接地以 `Y=58` 为准 | 接地点允许 `Y=57–59`；不得悬空或超过 `Y=59` |
| 标准人形有效高度 | 头顶至靴底 `44–48 px`，生产目标 `46 px` | 同级单位高差不超过 `2 px`；武器可局部延伸，但不得形成连续遮挡墙 |
| 精英/首领有效高度 | 头顶至靴底 `48–54 px` | 以体量和轮廓区别普通单位；脚底和相邻格目标仍可读 |
| 四足／宽型有效轮廓 | 宽 `52–62 px`、高 `26–36 px` | 最低接地点仍对齐 `Y=58`，头部方向与四肢关系必须清楚 |
| 透明边界 | 四角透明、硬 alpha | 只允许 `0/255` alpha；无绿幕漏色、光晕或投影 |
| 有效轮廓 | 预留足够外缘以读清武器和姿态 | 标准主体建议约 `X=16–48`、`Y=20–59`；武器/盾具超出须在报告说明 |
| 缩放 | 最近邻、整数倍 | 禁用抗锯齿、平滑、非整数缩放 |

> 2026-08-22 群体比例锁：`64×64` 画布、`X=32`、`Y=58`、标准人形 `46px` 目标高度与 `12–14px` 头高共同构成群体门禁。正式资产必须在原生逻辑像素中绘制或清理；禁止在 Unity 中使用非整数缩放补救比例。所有候选先进入同屏群体接触表，比例不协调即退回。

## 3. 视角、姿态与可读性

- 使用与当前正交战棋相容的**近顶视三分之四角**：头肩、躯干、脚底和主武器都能读出，不能做正侧视、透视立绘或伪等距立绘。
- 默认面向右下（屏幕东南）；未来朝向变体沿相同中心线、脚底基线和武器起点镜像/重绘，不能改变占格。
- 单位在 1× 时应先读到阵营、兵种和战斗姿态；4× 时才读取布料分层、皮革绑带、木石导具、锻铁护片和少量刻纹。任何文字、徽章字母、线缆、仪表或发光节点均不可作为识别信息。
- 阴影如需要，只能是紧贴脚底的 1–2 像素深色接地形，不得延伸成软边投影或遮住格位。

## 4. 阵营与色彩预算

| 组成 | 主色与预算 | 禁止项 |
| --- | --- | --- |
| 中性结构 | 粗布灰、皮革棕、木色、石灰、锻铁；约 75–90% 可见面积 | 大面积机械装甲、镀铬、高饱和金属、纯白外壳 |
| 友方/通用以太 | 冷青只用于符文、晶体、药剂或导具核心；约 3–8% | 用冷青填满制服；LED 式节点与电路线 |
| 敌方威胁 | 氧化红用于识别带、武器发热区或护甲边缘；约 5–15% | 与冷青共同成为大面积主色 |
| 交互/装备提示 | 安全黄橙仅为锁扣、弹药/医疗标记或小型警示；不超过 5% | 取代敌我阵营主色 |
| 调色板 | 静帧最多 24 个可见 RGB 色 | 抖动、渐变、半透明烟雾或未定义发光色 |

## 5. 兵种轮廓合同

| 类型 | 1× 必须可读的主特征 | 禁止混淆 |
| --- | --- | --- |
| 主角/游击者 | 单手武器或步枪、轻型战术外套、小型以太导具 | 不得像重甲盾卫或披袍术师 |
| 步枪兵 | 一支长而直的步枪，枪口朝向明确 | 不得以短枪或法杖替代 |
| 盾卫 | 身体一侧的大宽盾，护甲体量更厚 | 盾牌不能小到像手枪或背包 |
| 术师/净化者 | 导具、导管/线缆和受控以太组件 | 不得使用法袍、圣光、漂浮符文等中世纪语汇 |
| 突袭者 | 轻装、短枪/短刃、前倾机动姿态 | 不得与步枪兵的长枪轮廓相同 |
| 精英/首领 | 更大体块、加固护甲、额外能源模块或独特主武器 | 不能仅把普通兵换成更亮颜色 |

## 7. 人物静帧 QA 门禁

1. **来源：** 原图是单人单图，文件名、生成提示词和使用范围可追溯。
2. **规格：** `64×64`、硬 alpha、最多24色；标准单位主体高度 `44–48px`、目标46px，精英／首领 `48–54px`，四足宽 `52–62px`／高 `26–36px`；正式输出禁止运行时非整数缩放、自动裁切拟合或破坏锚点的重定位。
3. **锚点：** 4× QA 图叠加 `X=32` 与 `Y=58`，记录边界与接地点。
4. **轮廓：** 在 1×、4×、灰阶和透明棋盘格背景中检查；兵种的主特征必须保留。
5. **语义：** 确认为质朴、偏西幻魔法侧的学院／地区语汇；以太通过符文、法杖、符册、药剂、刻阵与手工媒介表达，不以高科技装备替代职业轮廓。
6. **批准：** 原料、规范化PNG、1×／4×／灰阶／棋盘格、群体应用接触、调色板、机器报告与人工审美结论齐全后可升为 `FORMAL_CANDIDATE`；Unity 导入再检查稳定GUID、Sprite、Point、Clamp、PPU32、无mipmap与整数缩放，通过后才升为 `FORMAL`。

## 8. 首批执行顺序

1. 用本规范复核现有 `hero`、`rifleman`、`shieldguard`、`pyromancer`、`raider` 与 `elite` 的原料证据。
2. 新增人物时优先补齐尚无独立原料或兵种轮廓不清的单位，不以重复生成已有兵种为目标。
3. 动画仅在相关静帧 `FORMAL` 后再立项；每帧沿同一 `X=32` / `Y=58` 规范单独 QA。
