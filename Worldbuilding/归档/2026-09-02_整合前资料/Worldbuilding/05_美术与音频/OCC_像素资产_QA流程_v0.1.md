# OCC 像素资产 QA 流程 v0.1

> 适用范围：剧情模式与肉鸽模式共用的战斗图标、地块、单位和像素动画。此流程只认证可追溯的独立原料；不把 AI 拼板、概念图或运行时矩形当作正式美术。

> **规范从属：** 本流程是 `OCC_美术规范_v0.1.md` 的执行门禁，不是平行规范。尺寸路由、来源、风格与状态晋级以总规范为唯一依据；本文件不得覆盖总规范。机器镜像为 `Tools/OCCArt/occ_art_contract_v1.json`。

## 状态与目录

| 状态 | 含义 | 可进入 Unity 正式 Assets |
| --- | --- | --- |
| `CONCEPT` | 氛围、材质或轮廓参考；不可切片、不可验收 | 否 |
| `PROTOTYPE` | 可用于当前功能占位，尚未通过完整像素 QA | 否 |
| `QA_PENDING` | 已有独立原料，正等待本流程复核 | 否 |
| `FORMAL_CANDIDATE` | 已通过机器合同与人工审美，等待Unity导入评审 | 否 |
| `FORMAL` | 已通过稳定路径／GUID、Importer、运行时应用与正式清单复核 | 是 |

- V2-04 路径只保留为首批历史记录。新生产放入对应正式美术生产批次的 `raw/`、`normalized/`、`QA/`，并附 `occ-art-manifest-v1`；在验证器与人工审美均通过前不得复制到 `UnityProject/Assets/`。
- 每项提交使用 ASCII 文件名：`occ_<category>_<name>_vNN.png`。动画帧使用 `..._f00.png` 起的连续独立帧；禁止先拼成伪雪碧图再切片。
- 审查输出放在同级 `QA/`，每项至少包含放大预览、网格/中心线/基线标记预览、调色板和一份 QA 报告；批准后才可生成 strip、GIF 或 Unity 导入副本。

## Gate 0：应用环境与屏幕占位

在任何生成、绘制或尺寸规范化前，先登记：实际界面／地图、逻辑占格、运行时绘制矩形、默认与最小分辨率的物理像素倍率、相邻单位／覆盖层／文字、允许越格方向及遮挡优先级。未取得真实运行时矩形或实战截图的资产不得进入批量生产；单资产画布规格不能替代应用环境证据。

## 通用门禁

| 检查项 | 通过条件 | 不通过处置 |
| --- | --- | --- |
| 来源 | 能指出独立绘制或独立生成的单图原料；不是从 AI 拼板硬切 | 标 `CONCEPT` 或重做原料 |
| 尺寸路由 | 16px语义图、24px材质源→32px交付、32px装备／单格物件、`(W×32)×(H×32)`多格物件、64px单位分别匹配机器合同；动画每帧固定 cell | 标 `QA_PENDING` 并按正确角色重做，禁止强塞32px |
| 像素边界 | 最近邻缩放后无半透明晕边、裁切、漏色或非整数缩放痕迹 | 修复透明边界后复审 |
| 调色板 | 记录色表及色数；关键材质色族达到 manifest 登记的最小像素数；冷青、锈红、安全黄橙只作局部语义色 | 调整并复审；关键材质消失必须失败 |
| 轮廓与语义 | 在1x、4x、灰阶和实际应用接触中均可辨认类别、方向与功能；质朴西幻魔法侧、材质和视角通过人工审美 | 任一失败即退回，不得记作以后再优化 |
| 归档 | 原料、审查预览、报告、审核日期和结论均可定位 | 不得升为 `FORMAL` |
| 来源渠道 | manifest 声明批准的直接图像原料或 PixelOver／Aseprite人工制作；无本地工作台、localhost或私有relay | 直接失败并保留历史证据，不得自动回退 |

## 类别附加门禁

| 类别 | 附加检查 | 通过条件 |
| --- | --- | --- |
| 语义图标 `16×16` | 单一功能 | 灰阶和目标UI尺寸下仅凭轮廓可辨；≤4色，无完整物件、材质纹理、文字或未定义符号 |
| 材质拾取物 `24×24→32×32` | 材质与槽位 | 原生24px先通过，之后严格以 `(4,4)` 无缩放嵌入32px；瓶、食物、金币等材质结构仍可读且槽位有呼吸边 |
| 装备／法术 `32×32` | 装备功能 | 方向、主轮廓与关键材质在1×及正式槽位中成立；不含AI伪文字或无来源发光 |
| 单格地块／对象 `32×32` | 格位与遮挡 | 逻辑占格 `[1,1]`；轻掩体低短可越视，重掩体更高更厚；功能轮廓可读 |
| 多格对象 `(W×32)×(H×32)` | 诚实占格 | manifest明确逻辑占格；跨格中线不割裂主体，不得缩为单格或虚报碰撞；应用接触按完整占格检查 |
| 单位 `64×64` | 锚点和兵种表面语义 | 中心线 `X=32`；脚底基线 `Y=58`；标准人形44–48px、精英／首领48–54px；由武器／导具和体量辨认，头部12–14px可读 |
| 动画独立帧 | 帧一致性 | 每帧沿同一中心线和脚底基线对齐；透明边界、色表和 cell 不漂移；再制作 strip/GIF/QA sheet |

## 审查顺序与结论

1. 制作者先填写 `occ-art-manifest-v1`：稳定资产ID、角色类型、逻辑占格、源／交付画布、运行时绘制矩形、默认／最小倍率、来源渠道与哈希、色数预算、关键材质色额和证据路径，状态设为 `QA_PENDING`。
2. 运行 `Tools/OCCArt/validate_occ_art_asset.py`；机器检查必须通过，且报告不得由制作者手填覆盖。
3. 审查者在1x、4x、灰阶、透明棋盘格和实际应用接触图中检查。对单位／动画叠加 `X=32`、`Y=58`；对地图物件叠加完整逻辑占格而非固定单格。
4. 人工审美结论必须明确为 `PASS`，包含审查者、日期和“轮廓／材质／视角／风格／应用”五项；缺一项仍为 `QA_PENDING`。
5. 机器与人工全项通过后才可将资产清单状态改为 `FORMAL_CANDIDATE` 并发起Unity导入；导入后复核稳定GUID、Sprite、Point、Clamp、无mipmap、PPU32或语义图PPU16与整数缩放，完成后才标记 `FORMAL`。
6. 任一项失败则保留 `CONCEPT`、`PROTOTYPE` 或 `QA_PENDING`，记录返工原因，只返工失败资产／失败环节；不得以功能可运行、机械报告或整批重生成代替美术验收。

### 纯地板附加门禁

- `32×32` 是玩法格交付尺寸，不是单块石板／木板的默认尺寸；报告必须记录默认与最小分辨率中每玩法格可见的材质模块数量与缝宽。
- 同族 A–D 必须生成全组合边缘矩阵，逐像素验证任意右→左、下→上拼接；任一组合有边缘 mismatch 即失败。
- 12×9 混铺中不得出现按玩法格重复的闭框、L 角、双线或断口；材质接缝应跨玩法格继续，临时范围覆盖层与地面纹理必须可分层阅读。
