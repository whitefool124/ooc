# OCC 首区关卡系统 v0.1

> 状态：关卡布局与遭遇实现基线。肉鸽敌人数值、护盾、破势与固定首领身份以 `OCC_肉鸽模式策划总纲_v0.2.md` 覆盖；Unity 中的旧护甲／破甲／两首领种子为实现债。剧情探索不增加倒计时、敌情推进或拖延关门机制。

## 1. 时代与内容边界

- 当前故事时间为主角 14 岁入学期，社会技术基底接近第一次工业革命前；常规战争使用冷兵器与弓弩，少量专用魔导器物由魔法师供能、校准和维护。
- 首区只使用石路、驿站、工坊、石闸、传讯塔、封存库与导能柱等当代可成立场所。运行时保留旧节点 ID 兼容存档，但玩家可见名称、地形语义和战斗编成不得出现铁路、现代枪械、狙击、现代爆破兵或成熟工业军队。
- 所有术式、屏障、刻印、显影、束缚与导能装置只来自以太素，不引入第二能源、智能异族或现代污染变异敌军。

## 2. 运行时合同

每个关卡定义必须包含：稳定 `level_id`、显示名、12×9 地图尺寸、目标类型/说明、难度阶、英雄出生格、敌人原型与精确出生格、轻/重掩体、可破坏导能目标、地面主题、精英/首领标记和前置关卡。

- 数据目录是地图、敌人编成和旧遭遇接口的单一事实源；场景 Marker 只保留为非目录演练的兼容回退。
- 构建器必须从定义直接生成 `GridMap`、`UnitState`、`CombatObjective`，并调用敌人原型应用数值、技能、ArtId 与 AI 所需稳定 ID。
- 关卡不得把敌人、英雄、重掩体和目标放在同一格；所有位置必须在边界内。破坏目标至少一个；歼灭目标不依赖装置。
- 关卡解锁由现有肉鸽节点图负责，关卡定义记录战斗内容阶次与直接前置，供独立关卡入口和测试审计；无现实时间限制。

### 3.1 弱／强遭遇池与地图抽取

首区采用弱遭遇池、强遭遇池、精英池和固定首领四层。池的单位是已审核的“敌人编成 + 地图语法 + 出生关系 + 奖励档”遭遇包，不允许先随机敌人再随机底图。

- 弱池使用 `OCC_首区敌人扩展包_v0.1.md` 登记的六组二人编成；起点周围至少两个普通战节点为弱池，地图必须提供一个不承受重叠威胁的首回合方案。
- 现有六组三人普通编成全部保留为强池；中庭／教学区以弱池为主，工坊／郊野／封存外环可按公开威胁与种子抽取强池。玩家可以提前挑战强池，但确认页必须先显示风险、编成和更高奖励档。
- 池归属在整张 40 节点地图生成时固定，不按玩家已经打过几场在进入节点时偷偷换池；已揭示内容不得重掷。
- 相邻战斗节点不得重复同一 `variant_key`、底图或主要空间命题。同一底图的弱／强变体必须改变敌人关系和首两回合选择，不能只删一名敌人。
- 强池奖励必须严格高于同区弱池的对应奖励档；具体增量属于奖励表任务。本阶段只冻结“风险与收益同时公开”合同，避免弱路线严格支配强路线。

弱池允许使用四种低压空间语法：

| 语法 | 结构 | 主要选择 | 禁止项 |
| --- | --- | --- | --- |
| 半开放演练场 | 玩家从下侧偏中进入，两敌分处斜前两翼 | 快速穿中还是从外侧逐个处理 | 出生区双线覆盖 |
| 回廊折角 | 两个开放区以宽折角相连 | 主动穿线还是退过折角重置距离 | 单格门与无法绕开的长直射线 |
| 环形练习场 | 中央重掩体／训练设施形成双向绕行 | 顺时针切支援还是逆时针迎击近战 | 中央万能落点 |
| 双台校准场 | 两个错位安全区之间有短暴露带 | 在蓄势前还是攻击后转移 | 唯一安全格或连续双控制 |

### 3.2 九关空间关卡设计重构（当前主线）

当前九关已经满足稳定 ID、独立敌群、目标与出生位的数据合同，但尚未形成九种足够不同的空间问题。现有实现中九关英雄均从 `(1,4)` 出生，敌人均集中在地图右侧；三张破坏关的导能目标都位于 `(10,4)`，多数掩体采用上下镜像排布。它们在数据签名上不同，但玩家开局通常仍是“从左向右推进、占据中央掩体、依次处理右侧敌人”。当 18 个普通与 6 个精英槽位复用这九张底图时，这种重复会被进一步放大。

关卡设计不扩充节点数量，也不先生产更多地砖。三个首批代表关继续作为原型，但其空间语法扩展为九关完整骨架：

| 原型 | 首个关卡 | 玩家要解决的问题 | 必须形成的空间差异 |
| --- | --- | --- | --- |
| 开阔交叉线 | `rail_patrol` | 选择正面压盾、侧翼切远程或先处理牵引者 | 非镜像出生；至少两条暴露与掩护成本不同的推进线；中央掩体不能成为严格最优的唯一落点 |
| 目标争夺 | `relay_raid` | 在拆导能目标与削减敌方行动之间分配回合 | 目标不得固定复用 `(10,4)`；至少一条快速高风险路线和一条较慢低暴露路线；守敌不能全部堆在目标同一侧 |
| 狭口拆链 | `elite_foundry` | 判断先突破先锋、切断修补链，还是绕路直取目标 | 形成可绕行的狭口而非单格门；修补师、先锋、目标构成可读但非线性的维护链；近战与远程开局都不能被单一路线淘汰 |

| 关卡 | 空间语法 | 核心结构与方向差异 |
| --- | --- | --- |
| `rail_patrol` | 开阔交叉线 | 玩家从斜下方进入三股威胁交界；盾术生守中但不封路，火矢与侧锋分处不同方向 |
| `depot_wreck` | 三口收束 | 玩家靠近中部，猎兽最快、检验偶最慢、约束助教从第三方向封线；至少一条路线能拆开追击节奏 |
| `relay_raid` | 偏心目标争夺 | 目标位于侧向或近中央；快速路线穿过重弩线，安全路线先处理远程但允许近战接近目标 |
| `signal_hub` | 三角维护网 | 助教、巡查员和盾术生形成非线性三角；玩家可从三条维护关系中的任一处切入 |
| `gatehouse` | 双向门厅 | 玩家位于门厅内部或侧翼；两条宽通道分别受盾线和重弩影响，并在中段允许换路 |
| `transmission_tower` | 中央装置三扇区 | 目标近中央，三名敌人与玩家分处不同扇区；任何位置只能屏蔽部分远程压力 |
| `elite_foundry` | 编织狭口 | 两条宽路线中段短暂交会，再分别通往目标和护障助教；教官不能以单格封死两路 |
| `core_approach` | 对角封线 | 重弩与约束分别控制两条对角方向，教官在中心移动；外围保留较慢的低暴露路线 |
| `core_finale` | 中心核心与外围维护 | 首领居中、支援分布外围；玩家从外围缺口进入，先拆哪条维护链决定后续环绕方向 |

模块化正式战场按 `32×32` 逻辑格重组庭院、道路、遗迹和夯土，不使用关卡专属整图。`signal_hub` 与 `gatehouse` 共用一个 `6×2` 北侧高台模块：高台两翼在 `(3,7)／(4,7)／(7,7)／(8,7)` 与 `(3,8)／(4,8)／(7,8)／(8,8)` 为永久结构阻挡，中央 `(5–6,7–8)` 为两格宽可走台阶。`signal_hub` 的第二路线锚点据此为 `(5,8)`；`gatehouse` 保留 `(6,8)`。永久阻挡必须与结构轮廓一致，不得由透明图或装饰墙谎报碰撞。

不得以仅更换敌人名单、地面主题或奖励权重冒充新关卡。每张正式关卡至少需要一个独有的空间命题，并说明：首回合可见信息、两条以上可行路线、主要风险、反制窗口、失败后的可归因原因，以及它与同阶其他关卡的区别。

### 3.3 地图与敌群组合门禁

- 石索束缚与重弩重击不得落入单出口长走廊；三近战不得落入只能由一格通过的瓶颈；三远程不得在玩家第一次行动前形成不可规避的交叉射线。
- 盾术生与护障助教不得布置为玩家无法接近助教的封闭前后排；检验偶与教官不得同时封住两条完成路线。
- 玩家出生、敌人、重掩体和任务目标继续遵守不重格合同。所有完整射线、束缚范围、维护目标、任务完成条件和强池奖励档在确认或首回合开始前公开。
- 破坏目标战采用“破坏全部任务目标立即完成”：不要求继续清理残余陪练单位，不追加隐藏惩罚、增援或倒计时；确认页公开该完成条件。快速高风险路线以承受公开火线换取直接完成，较慢低暴露路线通过先减员降低风险。
- 近战、远程、通用三种首发均须拥有至少两条可完成路线；任何优势位若同时提供最短路、最高防护与最佳射程，判定为严格优势并返工。

首轮验收采用固定种子与同一套三种首发构筑（近战、远程、通用）做 A/B 对照：记录前两回合落点、首个攻击目标、首次受击来源、完成回合数、剩余生命／个人魔力和战术重开。先验证 `rail_patrol`、`relay_raid`、`elite_foundry` 三个代表灰盒，再将同一合同扩展到九关及弱池四语法。通过条件为相邻节点不重复编成／底图／空间命题，弱池至少存在一个零重叠威胁的首回合方案，强池的首两回合路线与目标优先级产生可解释差异；每关至少存在两条能完成目标的路线；失败信息能指向玩家已看见的站位、射线、束缚或维护链，而不是隐藏增援或不可预览惩罚。

## 4. 视觉与反馈

- 已有关卡地面只复用通过 QA 的 `floor_plain/floor_industrial/floor_hazard`、轻/重掩体、导能目标和战利品箱；九关运行时不绘制铁路地块。
- 单位继续使用十张独立 64×64 正式像素图及既有攻击/施法/受击/恢复/VFX 语义；关卡系统不得用场景旧 Marker 名称或错误单位图替代。
- 1920×1080 与 960×540 均保持左战场 75%、右 HUD 25%，敌人出生格、掩体线和目标必须可辨。

## 5. 验收

1. 九关能由稳定 ID 构建不同地形、目标和精确编成；未知 ID 明确失败或走已声明的演练回退。
2. 十个敌人全部通过真实关卡构建进入运行时，其技能、状态结算、AI 和正式 ArtId 可解析。
3. 旧遭遇目录从关卡目录派生，不再维护第二份敌人名单。
4. 首区玩家可见关卡名、任务摘要、敌人和活跃战斗无步枪、狙击、现代枪械/爆破或铁路语义。
5. 全量 EditMode、必要 PlayMode、Unity 编译/Console、双分辨率战斗回归和场景 clean 通过。
