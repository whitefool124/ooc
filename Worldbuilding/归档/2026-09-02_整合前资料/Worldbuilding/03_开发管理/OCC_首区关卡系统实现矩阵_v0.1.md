# OCC 首区关卡系统实现矩阵 v0.1

> 日期：2026-08-08。实现源为 `FirstRegionLevelCatalog`；九个旧节点 ID 只保留作存档兼容，玩家可见语义以本矩阵为准。

## 1. 旧实现到最终方案

| 旧实现 | 最终方案 | 修订结果 |
| --- | --- | --- |
| 九个遭遇仅保存敌人 ID 列表 | 九个强类型关卡定义地图、目标、地形、精确出生位、阶次、主题和前置 | 同图换名单已退役 |
| 战斗始终读取场景 Marker 的一张 12×9 地图 | 首区 ID 由关卡构建器直接生成 `GridMap/UnitState/CombatObjective`；Marker 只供非目录演练回退 | 活跃关卡不依赖场景旧敌人 Marker |
| 遭遇目录与地图构建分离 | `RogueliteEncounterCatalog` 从关卡目录派生 | 消除第二份敌人名单 |
| 铁路、货场、铸造厂、精炼厂、传输塔与步枪兵旧文案 | 石路、驿站、刻阵工坊、以太校准室、传讯塔；敌人摘要由当前十敌人原型生成 | 玩家可见首区语义回到入学期技术基线 |
| 地面固定绘制铁轨/黄黑工业警示纹 | 关卡主题只使用石庭可读的 `floor_plain/floor_industrial` 组合 | 活跃九关无铁轨与现代警示带轮廓 |
| 单位纹理加载器按运行时 ID 猜文件名 | 按 `FormalArtRegistry.ResourcePath` 加载，并允许敌人原型显式 `ArtId` 处理既有首领复用 | 十敌人和两种子首领运行时纹理缺失 0 |

## 3. 闭环矩阵

| 层 | 实装 | 验收证据 |
| --- | --- | --- |
| 数据合同 | 关卡/敌人/地形强类型定义、稳定 ID、尺寸/阶次/前置/主题 | `FirstRegionLevelCatalog.Validate()` 无错误 |
| 构建 | 生成地图、英雄、敌人、目标；敌人原型应用数值、技能和 ArtId | 九关构建测试通过，出生位无重复/越界 |
| AI/结算 | 构建结果保留 `EnemyArchetypeId` 与专属技能，继续走 `EnemyTactics/CombatResolver` | 九关全部放置敌人可稳定给出战术命令；修补师实战 `UseSkill` 将先锋护盾 `1→5` |
| 遭遇/进度 | 旧遭遇 API 从关卡派生；现有节点图继续负责路线解锁 | 九关编成与精英/首领标记逐项一致 |
| 表现 | 注册表路径加载十张正式单位图；首领按显式 ArtId 复用既有精英图；关卡主题不绘制铁轨 | `relay_raid/core_finale` Play Mode 纹理缺失均为 0 |
| 时代 | 玩家可见关卡名、目标、敌人摘要和奖励显示迁移到当前时代；内部旧 ID 不改存档 | 关卡可见面禁词测试通过 |
| 自动化 | 新增 9 项关卡系统测试并跑全量 | EditMode 242/242、PlayMode 1/1 |

## 4. 非目标与兼容

- 不修改或保存 `CombatPrototype.unity`；场景中的旧 Marker 只供未登记演练回退，首区九关不会读取其敌人或地形。
- 不替换既有十张单位资产，不新增倒计时、时间压力、第二超凡来源或智能异族。
- `rail_patrol/depot_wreck/elite_foundry/transmission_tower` 等英文内部 ID 与旧任务模板 ID 为存档/测试兼容键，不进入玩家可见标题或战斗语义。
