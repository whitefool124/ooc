# COMBAT-FLOW-01 敌方逐行动演出实施计划 v0.1

## 1. 问题与目标

当前 `CombatPrototypeBootstrap.Update` 在检测到敌方行动者后立即完成“取计划、结算命令、结束回合”。多名敌人会在连续帧内完成全部状态变化，现有移动、攻击、受击和浮字虽然被发布，但没有足够的观察窗口，玩家难以辨认是谁行动、做了什么、造成了什么结果。

本任务只调整执行节奏与表现，不改变任何战斗决定。公开意图与实际执行继续消费同一份 `EnemyTurnPlanBook` 权威计划；`EnemyTactics`、命令合法性、AP、伤害、行动时间和状态生命周期保持不变。

## 2. 冻结流程

每名敌人依次经历：

1. **聚焦：** 行动者获得高亮、格子脉冲和“敌方行动”提示；HUD 有时间读出行动者与公开意图，战斗状态不改变。
2. **结算：** 只提交一次预先取得的权威命令；移动、攻击、技能和恢复仍通过既有 `CombatEffectExecution` 与 `CombatVisualFeedback` 发布。
3. **结果停留：** 根据命令类型保留足够时间显示位移、施术、受击、护盾、浮字和倒地；期间不得开始下一名敌人的命令。
4. **结束行动：** 当前敌人仍为行动者时才调用权威 `EndTurn`。
5. **行动间隔：** 短暂停顿后允许下一名敌人进入聚焦；英雄回合开始后不额外阻塞玩家输入。

建议初始节奏：聚焦 `0.65s`；移动结果 `0.70s`；攻击结果 `0.90s`；技能结果 `1.00s`；其他结果 `0.75s`；敌人间隔 `0.30s`。这些是表现时长，不属于战斗数值。

## 3. 架构边界

- 新增纯 C# `EnemyTurnSequence`，只管理阶段、截止时间和一次性信号，不读取或修改 `CombatState`，不持有 `EnemyTactics`，不重新决策。
- `CombatPrototypeBootstrap` 是唯一协调者：在聚焦开始时从 `EnemyTurnPlanBook` 取得一次执行命令，收到时序信号后提交或结束回合。
- `CombatVisualFeedback` 只消费行动者和公开意图，负责提示卡、聚焦脉冲和更清晰的动作时长，不持有或执行 `CombatCommand`。
- 权威命令提交后继续显式失效计划；下一状态需要计划时由既有计划仓刷新。
- 使用 `Time.unscaledTime`，避免帧率和战斗暂停造成同帧连跳；动画强度只影响位移幅度，不取消信息停留。

## 4. 测试优先矩阵

- 聚焦开始不会立即发出结算或结束回合信号。
- 到达聚焦截止时间只发出一次结算信号。
- 结果停留结束前不发出结束回合信号。
- 移动、攻击、技能使用不同结果时长，且技能不短于攻击、攻击不短于移动。
- 结束回合信号只发出一次；重置后才能开始下一行动者。
- 活动敌人变化、死亡或命令异常不会重复提交旧命令。
- 展示层不调用 `EnemyTactics.Choose`，实际命令仍来自 `EnemyTurnPlanBook`。
- 全量 EditMode、编译、Console 和场景 dirty 检查通过。

## 5. 验收与授权门槛

自动化验收覆盖规则同源、逐阶段信号和异常恢复。由于实际“快慢”和视觉显著程度只能在运行态判断，本任务在未获本轮明确授权前不进入 Play Mode、不保存场景；代码、EditMode、资源与 Funplay 编译检查继续完成，并把双分辨率视觉验收记录为待授权项。

## 6. 实施与验证结果（2026-08-11）

- 已按冻结流程实现 `EnemyTurnSequence`，并由 `CombatPrototypeBootstrap` 串行协调敌方行动；权威命令仍只来自 `EnemyTurnPlanBook`，没有修改 `EnemyTactics` 或战斗数值。
- `CombatVisualFeedback` 增加当前敌人脉冲、正式行动标题签和公开意图摘要，并延长敌方移动、攻击、技能、受击及恢复的表现时间。
