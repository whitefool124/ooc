# OCC 体验与视觉收口开发计划 v0.1

> **状态：COMPLETE（2026-08-11）。** `UXVIS-01` 至 `UXVIS-08` 已按批准顺序完成并通过最终回归。
> **当前目标：** 完成已有战斗、地图、商店、背包/搜刮、奖励与设置等玩家界面的 UI 设计、交互优化、信息呈现与动画反馈，使其成为可直接承载后续事件内容、资源/养成策划和数据平衡的稳定产品外壳。
> **本轮明确排除：** 不设计、不扩写、不实装事件内容；不新增地图、敌人、法宝、元素、角色、资源规则或养成数值。内容堆量与平衡在本轮收口后再启动。

## 完成后的版本边界

本轮结束时，玩家可以在现有首区流程中以完整、统一、可读、可操作的界面完成战斗、地图移动、商店/工坊、背包/搜刮、奖励/结算、存档入口和设置操作；每个操作均有明确状态、结果和失败原因。此后开发主线只剩：

1. 按已确定的界面和系统接口填充事件、资源与养成内容；
2. 依据完整流程进行数值、掉落和经济平衡；
3. 在内容量达到目标后做发布级品质、性能和兼容性收尾。

## 任务清单与完成定义

### UXVIS-01：统一 UI 视觉语言与基础组件

- 统一所有正式界面的页面层级、标题栏、面板、按钮、卡片、标签、图标槽、状态色、字号、间距、描边、焦点和禁用态。
- 统一悬停、按下、选中、键盘/手柄焦点、不可用、危险操作和加载/无内容状态；移除开发用措辞与临时样式。
- 交付：可复用的主题/组件令牌及页面检查表；1920×1080 与 960×540 下无关键裁切、重叠或不可读文字。

#### UXVIS-01 实现清单（2026-08-12）

- **主题令牌：** `FormalUiTheme` 统一中性表面、抬升表面、交互底色、遮罩、生命/护盾/魔力状态色、字号、8 px 间距阶梯、32 px 图标槽与最小 40 px 交互高度。
- **组件状态：** `FormalUiButtonTone` 与 `FormalUiButtonPalette` 统一普通、主要、正向、警示、危险按钮的普通、悬停、按下、选中、禁用和键盘焦点反馈；`UiButtonFeedback` 继续作为唯一 uGUI 状态执行器。
- **页面接入：** 战斗 HUD、入口/地图/简报/设置/档案、确认/Toast、奖励结算、启动页与背包 IMGUI 统一读取语义令牌；入口和设置使用稳定焦点键；正式文案移除“完整切片、确定性规则、开发控制”等开发措辞。
- **页面检查表：** `FormalUiPageChecklist` 覆盖 `landing / map / briefing / combat / shop-workshop / inventory-loot / settlement / settings / archive`，逐页登记默认焦点、返回路径、禁用态与空内容态。
- **验证：** `FormalUiThemeTests` 覆盖字体/间距/图标/点击尺寸、五类按钮状态、颜色语义和九类页面检查表；聚焦与全量 EditMode、Funplay 重编译、Console、场景 dirty 和 `.unity` Git diff 必须通过。

### UXVIS-02：战斗 HUD 信息层级与操作闭环

- 梳理常驻、选中、悬停三层信息：当前回合、行动点/资源、行动选择、目标、范围、成本、敌方意图、伤害/状态结果、行动序列和战斗记录。
- 统一移动、攻击、技能、互动、搜刮、使用物品和结束行动的选择、预览、确认、失败反馈与取消/重选逻辑。
- 清理战斗中不应出现的开发诊断；保证鼠标与键盘/导航焦点均可完成同一套操作。
- 交付：任意战斗时玩家能回答“谁行动、我能做什么、目标是谁、会发生什么、刚才发生什么”。

#### UXVIS-02 实现清单（2026-08-11）

- **常驻层：** “本轮行动”同时显示当前行动者/剩余 AP，以及所选行动、成本、可执行性、目标与预计结果；行动序列和最近五条现场记录保持常驻。
- **选中层：** 右键敌人继续作为只查看目标，行动切换清除旧目标；Esc/手柄返回依次取消目标查看、取消已装载物品或非默认行动，最后才请求离开战斗。
- **悬停/焦点层：** 本轮行动、行动按钮、英雄概况、快捷栏和结算继续通过同一 `FormalHoverTooltip` 显示完整规则、敌人档案、伤害/状态结果与失败原因。
- **键盘/手柄战场选点：** `T`/右肩键进入选点，方向键/WASD/十字键移动，Enter/Space/南键确认，Esc/东键取消并恢复当前行动按钮焦点；仅调用既有 `HandleCellClick` 权威提交路径。
- **验证：** `CombatHoverInformationTests` 增加决策摘要、取消优先级与选点边界合同；不修改行动规则、数值、AI、地图、事件内容或场景。

### UXVIS-03：战斗动画与结果反馈收口

- 收口单位聚焦、移动、攻击、技能、受击、护盾/生命/以太变化、状态施加/消退、掩体/可破坏物、敌方逐单位行动、胜负和战术重开的时序与表现强度。
- 保证动画不吞输入、不跳过关键信息、不与 HUD/浮窗冲突；动画强度设置为 0% 时仍保留必要的信息停留和结果文本。
- 交付：每一次正式战斗命令有可辨认的起因、过程和结果，且连续敌方行动不会相互覆盖。

#### UXVIS-03 实现清单（2026-08-11）

- **命令时序：** 保留 `EnemyTurnSequence` 的聚焦、结算停留、单位间隔三段式权威时序；移动、攻击、技能分别使用不少于 0.70/0.90/1.00 秒的结果停留，序列拒绝并发敌方单位。
- **单位与格子通道：** 每个单位仅保留一个当前位移/攻击/施法/受击/恢复动作；每个格子仅保留一个正式 VFX，新结果替换旧帧，防止连续伤害、击破和状态表现叠压。
- **结果补全：** 生命、护盾、以太恢复、移动、状态施加、状态自然移除、可破坏物损伤/摧毁和胜负均进入统一 `CombatFeedbackEvent` 结果层；显式结算会同步缓存，避免下一帧重复播报。
- **0% 动画降级：** 统一 `CombatFeedbackPresentationPolicy`；关闭单位运动、VFX、脉冲、漂移/淡出和聚焦闪烁，但保留静态敌方行动提示、胜负卡、浮字结果及原有信息停留时间。
- **验证：** `CombatFeedbackEventTests` 新增动画阈值与状态移除差分合同；继续由敌方序列测试锁定一次性结算信号、动作间隔和重入拒绝，不修改战斗规则、数值、AI、地图、事件内容或场景。

### UXVIS-04：地图页面与路线交互收口

- 统一地图顶栏、资源摘要、节点状态、路径状态、图例、当前地点、可进入/受限/已完成/未知节点和节点详情的视觉语义。
- 优化节点选择、移动确认、返回、继续、存档恢复后定位与不可进入原因的反馈；让地图与战斗/结算返回形成连续页面体验。
- 交付：玩家不查文档也能判断下一步可去哪里、为什么不能去、去了会进入哪类现有流程；所有节点/路径在双分辨率下可点击、可读。

#### UXVIS-04 实现清单（2026-08-11）

- **非颜色语义：** `RogueliteMapVisualPresentation` 为当前位置、可前往、已清理、已访问、已知、权限不足、未知建立唯一中文状态标签与单字符标记；路径统一为可用、安全、受限、已知、未知五态。
- **稳定焦点：** 地图默认焦点改为存档恢复后的当前节点，节点使用 `map.node.{id}` 稳定键；选择后重建恢复到同一节点，保留 Unity 标准鼠标/键盘/手柄导航与既有取消/返回路径。
- **检查与确认分离：** 所有节点均可选择检查，未知节点只公开“尚未侦测/连接信息未公开”；真正移动按钮继续读取既有 `CanTravelTo` 并调用 `SelectMapNode`，不可达、权限卡和回访安全原因常驻显示。
- **路径与详情：** 路径在线宽/颜色外增加“可/安/锁/联/?”标记，图例同步；节点卡显示状态字，详情合并节点类型、摘要、已知连接、状态、限制和进入结果。
- **验证：** `UiPresentationModelsTests` 新增稳定焦点键、七类节点非颜色语义、五类路径和详情限制/连接合同；不修改地图拓扑、节点数据、解锁、奖励或无时间压力规则。

### UXVIS-05：商店、工坊与奖励页面交互收口

- 统一商品/装备/校准/奖励卡的比较信息、价格/成本、拥有状态、可购买/不可购买原因、确认、成功、失败、返回与已领取状态。
- 建立一次性领取、防重复提交、余额不足和背包空间不足等状态的明确反馈；让选择结果即时反映在资源、构筑、背包和下一场战斗预览中。
- 交付：玩家可在不依赖开发控制台的情况下完成现有商店、工坊和战后奖励的完整操作，并理解选择的即时后果。

#### UXVIS-05 实现清单（2026-08-11）

- **统一可执行性合同：** `RogueliteEconomyPresentation` 只读计算商店/节点选项、战后奖励与工坊装备的可执行状态、短标签和具体原因；权威提交仍使用现有 Run/Bootstrap 方法。
- **商店与节点选项：** 卡面在提交前显示资源成本、当前余额不足、已拥有和背包所需空位；不可执行项禁用并通过统一按钮反馈给出原因，不触发无收益结算或库存异常。
- **工坊与校准：** 已装备项明确标记并禁用；武器显示伤害/射程/穿甲相对当前值，已装备个人术式不兼容时说明先调整术式；校准继续显示一次性状态、2 以太成本和即时资源变化。
- **战后奖励：** 奖励卡显示可领取/已拥有/背包空间不足，法宝领取前调用同一 `FindFirstFit` 只读预检；首焦点跳过禁用卡。重复提交锁保留，异常时恢复按钮并显示失败反馈，不吞掉奖励状态。
- **验证：** `UiPresentationModelsTests` 新增货币不足、背包满和工坊术式不兼容三项合同；不修改商品池、价格、奖励池、库存尺寸/重量、装备规则或数值。

### UXVIS-06：背包、搜刮与快捷栏体验收口

- 完善背包网格、物品尺寸/朝向、拖拽、旋转、合法/非法落点、快捷栏关联、物品比较、数量/次数、重量、以太负荷和详情悬浮信息。
- 完善搜刮入口、战利品容器、拾取/放回、背包满、不可放置、消耗、跨战斗保留与恢复的可视回执。
- 交付：玩家可仅靠界面完成整理、使用与搜刮，并在每个失败状态知道阻塞原因与可采取的下一步。

#### UXVIS-06 实现清单（2026-08-11）

- **鼠标整理基线：** 保留既有 6×10 网格、按占格拖拽、拖拽中右键旋转、合法/非法覆盖、原子提交和失败保持原位；详情继续公开尺寸、朝向、次数、重量、来源、效果与风险。
- **键盘闭环：** 打开背包后自动选择首件物品；方向键按物品空间位置移动选择，`R` 使用同一旋转规则，数字 `1–8` 关联快捷栏，`F` 搜索或拿取首个已揭示战利品，`B/Esc` 返回战斗；搜索框聚焦时不劫持文字输入。
- **搜刮前置反馈：** 搜索区常驻相邻、1 AP、已清空原因；每件已揭示战利品使用与提交相同的 `FindFirstFit` 只读预检，显示可拿取的自动落位或背包无合法空位及具体库存错误。
- **快捷栏与持久化：** 键盘和鼠标仍只调用既有 `EquipInventoryQuickbar`、`ActivateInventoryQuickbar`、`SearchCurrentLoot`、`TakeCurrentLoot` 和 `NotifyInventoryChanged`，继续复用确定性命令与跨战斗存档路径。
- **验证：** `InventoryInteractionPresentationTests` 新增空间方向选择、拿取预览/提交同源、相邻/AP/清空失败原因共 5 个测试实例；不修改物品定义、容器尺寸、重量/负荷、AP 成本或搜刮规则。

### UXVIS-07：入口、存档、结算与设置页面收口

- 收口启动入口、新局/继续、存档错误/损坏保护、战前简报、胜利/失败结算、返回入口、设置与开发功能隔离。
- 明确长操作、存档写入、恢复、失败后果和删除/重置等危险操作的反馈和确认层；避免空白页、无焦点、返回死路或残留模态层。
- 交付：从启动到结束、退出后恢复的页面路径无断链，开发工具在正式体验中默认不可见。

#### UXVIS-07 实现清单（2026-08-11）

- **入口与恢复状态：** `MapSaveUiPresentation` 将暂无存档、可继续、损坏/非法且受保护、存储暂不可用和最近写入失败转换为非颜色标签；继续按钮不再把坏档显示成普通最近存档。
- **安全覆盖：** 新开局覆盖先在已确认的危险操作内读验旧槽；有效旧档由已验证写入的回滚路径替换，受保护坏档只在明确确认后清除主槽锁，首份损坏备份继续保留，存储异常时拒绝启动。
- **写入真实性：** 新推进首次写入成功后才进入地图；地图返回入口前再次保存，失败则保留运行内状态并停在当前页。设置继续即时生效，但持久化失败会明确提示且返回按钮不再声称已保存。
- **既有流程复核：** 启动页、简报、胜负覆盖层、奖励结算、确认层取消/焦点恢复和开发门控继续复用既有正式实现；未改变失败后果、存档槽数量、结算、事件或玩法规则。
- **验证：** `UiInteractionContractsTests` 与 `RogueliteSaveGatewayTests` 聚焦 22/22；全量 EditMode 341/341。Funplay 编译 0 error / 0 warning，Console 无 error，场景未脏且未进入 Play Mode。

### UXVIS-08：跨页面动效、可访问性与最终体验回归

- 收口页面切换、面板进入/退出、按钮回执、焦点迁移、提示/Toast、模态层、图标/VFX 使用规则，避免装饰性动画影响操作或可读性。
- 审查色彩以外的信息编码、字体/对比度、低分辨率可读性、0%/100% 动画、键盘导航和异常状态恢复。
- 交付：对战斗、地图、商店/工坊、背包/搜刮、奖励/结算、入口/设置进行完整体验回归；全量 EditMode、编译、Console 与场景脏状态通过。

#### UXVIS-08 实现清单（2026-08-11）

- **跨页面动效与恢复：** 复核页面淡入/局部位移、按钮回执、Toast 替换清理、确认模态取消/焦点恢复、结算卡错峰进入及 0% 立即终态；保留文字、图标、边框和结果标签，不让动画成为唯一信息载体。
- **全局可访问性：** `FormalUiTheme.ConfigureAccessibility` 令高对比与大号文字由所有正式 uGUI 页面共用；背包 IMGUI 同样读取响应式字号和对比令牌。高对比正文/说明与暗色面板满足可读对比，设置不再只影响少量战斗反馈。
- **双分辨率合同：** `UiLayoutContractTests` 对全部登记布局按真实锚点/枢轴投影到 1920×1080 与 960×540，逐一断言无越界；紧凑字号保持整像素，0%/100% 动效终态继续由纯合同覆盖。
- **正式非人物资产：** 扩展既有周边 UI 生成器，新增独立 `480×270` 背包仓储与结算归档背景；采用 OCC 受控调色板、硬 Alpha、无人物/伪字，接入运行时注册、Point/Clamp/无 mipmap 导入门禁及 QA 图/JSON。

## 推荐实施顺序

`UXVIS-01 → UXVIS-02 → UXVIS-03 → UXVIS-04 → UXVIS-05 → UXVIS-06 → UXVIS-07 → UXVIS-08`

该顺序先锁定共用视觉和输入规则，再分别收口战斗、地图和经济/物品页面，最后处理跨页面体验。每完成一项才允许开始下一项；发现会影响前序规则的缺口，回到前序任务修复，而不是在页面内临时复制实现。

## 本轮验收总线

- 所有已有正式流程可用鼠标和键盘/导航完成；每项操作有成功、失败、禁用、取消与返回状态。
- 1920×1080、960×540、动画 0%/100% 下，关键操作和文字保持可读、可达、无重叠。
- HUD、地图、商店/工坊、背包/搜刮、奖励/结算、入口/设置使用同一视觉语义和信息层级。
- 全量 EditMode 通过，Funplay 重编译 0 error / 0 warning，Console 无项目 error，退出 Play Mode 后场景不脏且不保存场景。
