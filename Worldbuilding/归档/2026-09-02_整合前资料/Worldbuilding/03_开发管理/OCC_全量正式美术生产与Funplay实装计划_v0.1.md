## 1. 已批准且不可回退的视觉基准

1. `ART-BASE-01` 32 色跨类别主色表已经批准：煤灰/铁黑为大面积结构，冷青=友方/可执行，氧化红=威胁/伤害，安全黄橙=交互/战利品，灰绿=治疗/护盾，暗紫红=污染/越限。
2. `ART-BASE-02 v0.2` 已批准：`1920×1080`，左战场 `1440`、右 HUD `480`；另须通过 `960×540`。
3. 地块、对象、图标使用 `32×32`；单位画布 `64×64`、中心 `X=32`、脚底 `Y=58`。
4. 标准单位主体有效高度约 `32–38 px`，精英/首领约 `38–44 px`；相对旧版约 70% 视觉轮廓。禁止在 Unity Transform 中直接使用 `0.7` 非整数缩放。
5. 正交方格、整数最近邻、硬 alpha、Point、Clamp、无 mipmap；不使用伪等距、模糊、抗锯齿或非整数像素采样。
6. HUD 为黑白/灰阶主导的极简工业细线框架；不得恢复厚重金属板、铆钉、浮雕、斜切装甲框或高密度机械装饰。
7. AI 图只作为独立原料；正式结果必须保留原图、规范化 PNG、调色板、1×/4×、灰阶、透明背景和 JSON QA。不得从拼板硬切。

## 3. 生产与实装执行顺序

### Gate 0：基线与清单审计

1. 读取当前待办、美术规范、QA、需求表、火系池和运行时代码。
2. 用 `rg`/manifest 枚举全部可达页面、单位、技能、状态、反馈、节点、装备和 Resource 加载点。
3. 记录 dirty worktree 基线，区分用户既有改动与本任务新增改动。
4. 用 Funplay 获取活动场景、Hierarchy、场景脏状态、编译和 Console 基线。
5. 输出“运行时 ID → 正式 asset ID → 路径 → 状态 → 使用页面/事件”的全量矩阵；矩阵未闭合不得宣称完成。

### Gate 1：模板、目录和自动 QA

1. 完成 `ART-BASE-03` 与目录规范。
2. 建立/复用规范化脚本：硬 alpha、色数、尺寸、中心/基线、拼接、动画 cell、GIF、QA、JSON。
3. 建立 Unity Importer 自动配置和覆盖测试；确保 Point/Clamp/无 mipmap/正确 SpriteMode、pivot、PPU。
4. 建立正式资产覆盖测试、禁止回退测试、重复映射测试和资源加载测试。

### Gate 2：静态资产全量生产

按“环境 → 单位静帧 → 基础图标 → 节点/物品 → 50 火系图标”顺序连续生产。每个独立资产使用独立原料；ImageGen 默认内建路径，一资产一调用；透明需求使用纯色绿幕后本地去背。每个小批次立即规范化并 QA，失败项仅返工失败资产，不重新生成已通过资产。

### Gate 3：动画与 VFX 全量生产

1. 先完成 12 单位行为矩阵，再逐单位制作完整动作；不为不存在的行为造动画。
2. 使用 Aseprite/PixelOver 或等效工具做人形动作和 onion-skin 清理；脚本只导出/验收。
3. 制作 24 基础 VFX 和 5 火系模板；建立触发事件和遮挡预算。
4. 输出每个动画/VFX 的独立帧、strip、GIF、QA、报告和事件帧记录。

### Gate 4：Unity/Funplay 正式实装

1. 先退出 Play Mode；通过 Funplay 确认场景、对象和 dirty state。
2. 将通过 QA 的资产复制到版本化正式目录；禁止直接覆盖无备份的旧资产，先保留 v01/v02 或迁移映射。
3. 通过 Unity Importer/Editor API 配置并读回导入参数；场景、Prefab、ScriptableObject 只通过 Funplay/Unity API 修改，不手改 YAML。
4. 建立正式 art registry 和 presentation binding，替换复用映射、占位矩形、无语义 glyph 和 prototype fallback。
5. 接入单位朝向/动画状态机、CombatEffect VFX、状态/环境、目标/路径、物件三段状态、HUD 图标、肉鸽页面和技能/物品图标。
6. 优先代码/运行时绑定，避免保存场景；只有持久场景/Prefab 结构确有必要时才保存明确目标，并立即读回与检查 diff。
7. 每次外部修改 `.cs`、`.asset`、`.prefab`、`.unity`、`.shader`、`.asmdef` 后执行 Funplay `request_recompile` → `wait_for_compilation` → `get_compilation_errors`；Play Mode 阻塞时先退出。

### Gate 5：自动测试与资产审计

- 运行现有全部 EditMode 测试，至少覆盖战斗解析、状态生命周期、技能组合、反馈语义、UI 交互、UI 布局、存档、20 节点完成线和两首领种子。
- 新增并运行：正式资产覆盖、导入参数、唯一兵种映射、状态/VFX 覆盖、火系 50 图标覆盖、节点图标覆盖、无 prototype fallback、动画 cell/锚点、场景引用完整性测试。
- 扫描缺失 Sprite、Missing Reference、粉色材质、Bilinear、mipmap、错误 PPU/pivot、非整数缩放、重复 asset ID、不可达/孤儿正式资产。
- 编译错误 0、编译警告 0（项目既有明确白名单除外且需记录）、Console 项目错误 0。

### Gate 6：Funplay 全流程视觉回归

1. 进入 Play Mode 后等待 reload recovery ready。
2. 以实际点击/输入走通：入口 → 新局/继续 → 20 节点地图 → 每类非战斗页面 → 简报 → 战斗 → 三选一 → 结算 → 存档恢复 → 两种首领 → 胜利/失败 → 档案/设置。
3. 使用固定种子覆盖两名首领、普通/精英/目标物破坏、箱体开启、六状态、八环境表现、护盾破裂、治疗/魔力恢复、移动/攻击/施术/互动/搜刮和至少五类火系 VFX。
4. 至少建立一张高密度遮挡场景，验证单位 70% 有效轮廓、相邻单位、掩体、VFX、意图、血条和目标格同时可读。
5. 对每个关键页面/状态保存 `1920×1080` 和 `960×540` Game View 截图；另生成接触表、灰阶、红绿色觉风险、动画 GIF 和 QA 总览。
6. 截图必须落入项目 QA 目录并建索引，不只留在 `Library/FunplayMcp`。

### Gate 7：终局清理与验收

1. 退出 Play Mode。
2. Funplay 检查 active scene、dirty state、Console；场景应 `isDirty=false`，除非计划内明确保存且已验证。
3. `git status` 逐项核对，只保留本任务和原有用户改动；不混入缓存、临时图或未审原料。
4. 更新正式资产清单、需求表、QA 流程、运行时映射、验证记录和当前待办。
5. 生成最终审查报告：资产覆盖矩阵、数量、路径、QA、测试、Console、双分辨率截图索引、已知排除项和最终 `COMPLETE` 结论。

## 5. 失败处理与停止规则

- 单项生成失败：保留已通过资产，只返工失败项；不得用未审图临时顶上。
- Funplay 在 reload 时 502/timeout：等待恢复、最小 ping、读回状态后继续；不得把通讯中断误判为实现失败。
- 测试失败：定位根因、修复、重编译、重跑受影响集合和全量回归。
- 场景/Prefab 修改超时：先检查是否部分成功，再决定继续或回滚；禁止盲目重复创建。
- 只有遇到会改变产品定义的未决定问题才停下请求用户；纯制作、导入、绑定、测试和返工由执行者自主完成。
- 不因“工作量大”“生成次数多”“已完成一个批次”“上下文即将压缩”或“预算预计较高”停止；跨上下文继续同一任务并读取本计划/待办/manifest 恢复进度。

- 在不返工基础 UI/动画/VFX 语法的前提下追加新地区、敌群和剧情阶段。
