# Unity 像素特效展示场

本次交付为剧情与肉鸽共用的表现测试场景，不新增玩法与伤害规则。场景路径为 `Assets/Scenes/PixelVfxShowcase.unity`，已加入 Build Settings，原 CombatPrototype 仍为首场景。

## 使用

Unity 菜单 `OCC > VFX > Open Pixel Showcase` 打开场景，然后进入 Play Mode。右侧七个按钮选择护盾受击、护盾碎裂、以太消解、空间冲击、像素折射、移动光源、护盾光效。点击左侧场地改变命中点；空格重播，P 暂停，O 对比原画；支持三倍慢放和光照强度滑杆。

场景内的地砖、三个单位、相机、显示区域和控制按钮均已保存。使用既有正式 PNG，不生成或替换资产。单位保持原画布与 32 PPU，主角 64×64 没有压缩成 32×64。

## 实现边界

- 左侧相机将真实 Sprite 场地渲染到 240×180 原生缓冲，再执行 Shader；与右侧 HUD 合为 320×180 逻辑布局。1920×1080 下严格六倍显示，其他尺寸按整数倍率加信箱边。
- 折射偏移为整数像素；光照与外发光采用分级色块。动态光照使用地砖边缘和单位 Alpha 推导的屏幕空间法线，并以十二步采样计算单位遮挡。这是二维近似，不是物理体积光或正式手绘法线。
- 展示场运行时克隆当前 URP 配置并把 renderScale 设为 1，避免工程原有 0.5 缩放破坏原生像素。场景销毁时恢复先前 QualitySettings 配置，共享 URP 资产不修改。
- 本轮完成专属展示场，尚未绑定正式战斗伤害、护盾和状态事件，也未重新构建 Windows 可执行文件。

## 验证

使用 Unity CLI 1.0.0-beta.11，在主工程 Unity 6000.5.2f1 中创建并保存场景。C# 编译完成，Shader 编译消息为空。

`verification.json` 与 `mode-0.png` 至 `mode-9.png` 记录 Play Mode 实测：七种模式按钮经过屏幕 Raycast 与点击事件，输出各不相同；暂停、慢放、原画对比、强度调节和场地命中输入已执行。模式切换会调用重播逻辑。`showcase-shield.png` 为最终真实 Game View 的 1920×1080 截图，修正了强度标签高度。

验证过程中 CLI 动态 eval 出现一次主线程超时，但任务随后实际完成并产出完整回执，未重复派发；之后一个只读 eval 遇到 Pipeline/Roslyn 的字符转换异常。最终重新正常进入 Play Mode、截图并退出，Console 实时计数为零错误、零警告，场景保存且无未保存修改。这些工具异常不属于场景 Shader 错误。

新场景没有直接写 YAML，场景与材质由 Unity Editor API 生成，补充场景字段和保存通过 Unity CLI 执行。新脚本、Shader、材质与场景均使用 Unity 生成的稳定 meta/GUID。
