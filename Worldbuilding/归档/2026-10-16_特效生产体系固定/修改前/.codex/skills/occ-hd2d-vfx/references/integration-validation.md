# 接入、质量与验证

这是一套待实施架构，命名均为建议，不能在代码尚不存在时声称组件已接入。复用现有动作时钟与结果事件，不另造战斗结算。

## 与当前工程连接

```text
真实结算与结果步骤
  CombatFeedbackPublisher / CombatVisualFeedback.Publish
  FireVfxSequence.From / NotifySkillDelivery
                  ↓ 保留命中前快照与动作播放时点
  既有动作队列 + CombatVfxPlayback（能力／反应分层）
                  ↓ 可增加表现适配器，不写战斗模型
  HD2D空间效果编排器（建议）
       ├─ 主体、轨迹、地面波、受光烟尘
       ├─ 池化瞬态光与局部折射
       └─ 已有UI结果／已有音效接口
```

`CombatVisualFeedback.cs`目前仍有Canvas、Graphic和屏幕反馈布局，同时使用 `Hd2DPreview` 的同相机位置投影；这证明接线基础存在，不证明世界粒子系统已完成。迁移时保留数字／功能反馈，逐族替换画面效果；新旧主爆发不能同时叠播。`EpicToonVfxShowcase`／`PixelVfxShowcase`只是研究入口。

建议表现配方数据携带：效果ID、已有结果种类、来源／目标／真实路径、实际受影响格、主形方向、锚定方式、主峰时点、生命周期、光包络、质量变体和资源引用。参数来自实际结算，外观随机使用独立表现随机源，不消耗游戏随机数。配置文件格式沿用工程既有方式，数据驱动不意味着必须新建ScriptableObject和改全库Prefab。

## 空间坐标

| 类型 | 应用位置 | 容易出错的点 |
|---|---|---|
| 地表环、范围、裂纹、水纹 | 水平地面，轻微深度偏移 | 屏幕圆代替透视圆；Offset过大漂浮；错误叠到物件之上 |
| 单位附着、施术点、受击 | 当前视觉位置与足点，必要时按面片局部偏移 | 从最终逻辑位置取起手；等待移动时效果提前跳到终点 |
| 投射与带状轨迹 | 实际来源到目标／真实逐格路径的世界空间 | 端点Canvas坐标直接当世界坐标；平移缩放后漂移 |
| 物块破坏 | 被破坏前的几何／位置快照 | 对象销毁后找不到碎屑来源；用已经变化的地面推断材质 |
| 数字、资源条、必要提示 | 保留现有二维反馈及同相机投影 | 世界景深模糊字；被空间粒子遮挡；拦截格子输入 |

场景独立图层、相机、Volume与RT由当前HD2D宿主管理。效果不能新增全局Volume污染其他页面，不能把RT输出UI层再照一次。宿主隐藏即取消效果；同尺寸战斗切换、读档和重开需要新的会话标识，旧回调不得落到新战局。

## 生命周期与性能

池化Particle System、Trail、Mesh效果、Light及必要材质实例。取得时完整设置位置、时间、颜色、方向、随机种子与强度；返还时停止并清空粒子、轨迹、光、声音和回调。禁用动画、中断、离页、重开、对象停用及关闭宿主共享取消入口；持久场地静态提示按真实状态恢复。

MaterialPropertyBlock适用于支持它的Renderer；先测SRP Batcher与批处理代价，不把“用了MPB”当作优化证明。uGUI遮罩派生材质仍服从现有独立材质经验，不能照搬Renderer方案。不要逐帧实例化材质或随每个火星创建光源。

先量无新增效果的基线，再量实际效果增量：CPU主线程、GPU、Overdraw、Draw Call／SetPass、GC和活动实例峰值。耗时单位ms，附GPU、分辨率、实际renderScale、质量档及测量窗口。60fps对应16.67ms整帧只是目标参考，当前未证明目标设备性能。

以下为初次样板的调校起点，不是硬门槛；以同场景实测和画面收益决定：

| 质量候选 | 粒子与空间层 | 瞬态光 | 折射／烟雾 |
|---|---|---|---|
| 基础 | 保留主形、轨迹、命中、真实场地，减辅助碎粒 | 每个主事件共享1盏无阴影光，按全局优先级分配 | 可省折射，烟片减层 |
| 华丽 | 主形＋次级碎屑＋尘圈＋受光烟＋余烬 | 建议全战场约4盏同时活跃起测；与环境光一起检查Forward每物件限制 | 局部折射和软粒子在输入确认后使用 |
| 英雄样板 | 增加形态变化、层次和更强局部峰值 | 优先提升包络与受光范围；有阴影爆发光单独测收益 | 可试VFX Graph／更复杂空气层，保留基础变体 |

同一作用区持续火场可共享灯或按亮度重要性选择，避免每格一盏争抢Forward灯槽。性能紧张先减少不可见层、透明覆盖面积、灯阴影和反射探针刷新频率，再降次级粒子；保留主形和真实结果。

## 验收样板

从正式入口进入真实战斗，使用正常配置执行一张合法现有术式。捕获起手、投递、命中和余波的连续记录，同时看战场与HUD。机器验证、实际画面、玩家审美分开登记。

| 验收问题 | 需要的证据 |
|---|---|
| 结算是否诚实 | 来源、受影响格和伤害与真实结果一致；零变化、挂载触发器不假爆；延迟触发不起手 |
| 是否处于3D空间 | 近墙、墙后、相邻单位、边界；平移／缩放后足点与轨迹保持；水纹尘圈贴地 |
| 照明是否真实 | 分开关闭粒子／灯对比；墙地受光随爆发变化，阴影代理无断切或悬浮 |
| 主峰是否好看 | 明暗背景均看得出主形；火带有方向、爆发有层次；运动而非单张截图证明节奏 |
| 是否仍可操作 | 峰值时落点、范围、脚下资源条及操作焦点可读，特效不接收射线；下一动作不被余波挡住 |
| 清理是否完整 | 关闭动画、离战、重开、同尺寸战局切换无残灯／尾迹／迟到声音和回调 |
| 是否可交付 | 源码改动后导入编译与Console；Shader错误和构建变体／资源包含；所改正式资产Importer与GUID复核 |

只检查受影响的高风险情况，不为纯技能准备启动Editor。实机阶段按Unity CLI技能核对主工程dataPath与场景脏状态，发现实际可用命令，必要时再使用允许的Funplay能力。

当前最合适的下一步是一个现有火术的空间爆破完整样板：先证明同步与接触，再调光与主形，最后增加折射和烟；成功后以配方变体覆盖同族，不先铺80张术式。
