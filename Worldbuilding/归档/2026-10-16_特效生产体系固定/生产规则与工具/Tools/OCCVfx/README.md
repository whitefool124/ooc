# OCC 像素特效生产入口

2026-10-16：用户认可天穹熔炉当前方向，要求固定体系、支持后续批量制作。当前参考为 **SkyFurnaceFractureFix_20261016**。源码、资源、场景配置和实机证据已按 SHA256 冻结在 [参考清单](references/sky_furnace_20261016.lock.json)。它是可复用的独立演出样板；正式 HD-2D 基线仍为 QA_PENDING，不能把这次方向认可扩散为新资产或所有场景的批准。

本入口是技术制作与验证说明。产品规则仍来自总案 A.2.2、A.2.4、A.3、A.5–A.6；本轮没有改变玩法、正式资产规格或同步母版。

## 已固定的制作选择

| 内容 | 制作方式 | 防止退回的错误 |
|---|---|---|
| 法阵、核心魔法主形 | 完整像素图片，一像素厚纸板，保留干净轮廓和图案 | 暴力裁切毛边；几条发光线代替完整造型；重新加天空体素炉体 |
| 引导、喷射、火星、吸收像素、冲击、烟尘 | 无贴图的一像素截面长柱或一像素正方体；烟尘使用原生 Particle System | 烟片、冲击圈图片、粗实体火流、球和多面体粒子 |
| 生长 | 少数起点，邻格色块长出、分枝、连接；未出现部分完全透明 | 暗底纹变亮、满圈撒点补图、角度扫出或仅给显现降帧 |
| 点亮与空间感 | 保留完整造型，完成后保持，再在释放时增强；纸板高低层次配合有限真实光源 | 全部同速旋转同亮；用 Bloom 或光线替代主形、爆发 |
| 后半段 | 核心释放、定向喷射、贴地冲击、火星和烟尘分工错峰 | 只有起手蓄力，没有主爆发和接触冲击 |
| 退场 | 完整纹样原位转成等量像素立方体，先保留全部纹素，再靠小碎块的位移拉开裂隙，带光飘走，移开后逐颗结束 | 整体 Alpha 渐隐；随机删像素形成覆盖率淡出；原地擦图后另撒无关粒子 |

Image 用于独立原料和审美参考。新图继续走现有 manifest、处理记录、资产验证与实际应用流程；上述积木不改变资产入库门槛。特效像素允许不同大小，但单颗尺寸和整团运动范围必须分开记录，与角色、范围和镜头协调。环境、角色与功能图标不适用特效尺度例外。

## 当前样板的数据与积木

当前样板使用 1/32 米像素间距；这是参考值。4 张法阵画布分别为 5/4/3/2 米，核心由 3 张交叉的 3 米纸板组成。另有 17 根长柱、36 个复用立方物件及 5 个原生 Particle System（烟尘、灰烬、冲击、火星、解体）。完整数据在 [样板配方](recipes/sky_furnace_v1.json)，不再使用旧版贴图烟尘清单。

解体实测：19703 个源纹素，外环 5468 个像素在 9.0–11.2 秒采样全部保留；同一粒子的原生回读颜色与 Alpha 保持不变，11.2 秒全部外环像素均已移动，最大约 1.22 米。整体解体运动跨度约 5.43×3.11×6.13 米，单颗边长 0.03125 米。上述数量不是通用性能预算。当前 16 秒、固定镜头、无声音和无地形破坏属于独立演出样板；实战沿用真实结算与动作窗口，不能复制成每次施法等待16秒。

| 已有实现 | 复用职责 |
|---|---|
| `PixelEffectCard` | 根据源 Alpha 建立一像素厚纸板及边界侧壁 |
| `PixelIgnitionMap` | 原生纹素出生顺序、邻格生长、少量根与分枝；计时图是技术数据 |
| `SkyFurnaceVoxelEmitter` / Smoke / Burst | 原生立方粒子的建立、确定性模拟、发射和清理 |
| `SkyFurnacePixelDisassembly` | 完整源图转粒子、小碎块分离、同 ID 原生回读、暂停/跳播一致性 |
| `SkyFurnacePixelLayer` / `SkyFurnaceSolidPixel` | 纸板受光/激活；辅助无贴图像素材质。当前辅助像素使用不透明混合 |
| `Hd2DFireLightRecipe` | 发光和真实环境照明分开，以有限光源承担空间受光 |
| `SkyFurnaceDirector` / Authoring / Verification / PlayerProbe | 已验证的编排与后台捕获、正常播放、暂停、重播、跳过、复位、清理样例 |

配方 JSON 是制作清单与检查输入，当前并非自动加载的 Unity 运行时配置。上述部分积木仍带 SkyFurnace 命名及样板时钟/尺寸依赖；新特效按配方接入这些积木并提供自身时点与锚点，不整份复制导演代码或把“已有字段”当成参数已经接线。

## 批量制作流程

1. 从模板建一个新配方，填写用途、来源/目标锚点、像素间距、主形/辅助分层、真实阶段时点、单片尺寸及整体运动上限。16 秒不是默认实战规格。小效果可明确跳过不需要的阶段并写原因。
2. 先做一个完整代表效果。`new`会给每项生成独立`capture_directory`；现有SkyFurnace捕获菜单仍写死旧归档目录，新效果适配捕获器时必须接到自己的目录，不能直接运行旧菜单覆盖冻结证据。图片按法阵/核心职责生成或复用，清理色块、轮廓和安全边；辅助层复用无贴图积木。保留新原料和处理来源。
3. 按真实动作时点接入，复用局部光与原生粒子，确认厚度、锚点、遮挡和世界尺寸。正式战斗适配读取真实来源、目标、路径和结算，不在特效中更改玩法。
4. 运行设计检查。检查模板完整性与几何/贴图/尺寸合同，不把它当作 Unity 导入或画面通过。
5. 运行受影响的局部实机检查：正常入口、正常速度、1920×1080 与960×540、主峰与退场、暂停/重播/复位/中断及资源清理。记录原生粒子同 ID 的位置、RGBA、尺寸、实际材质能量，以及发射域+速度+寿命产生的整体范围。先保持全部源像素，再用位移证明破碎；固定填写 Alpha=1 不是证据。
6. 每项新效果绑定自身实现指纹与证据，再做人工审美。代表项成立后按同一配方族扩量；变体也必须重新核对世界尺寸、时序和主形。新 ID、改源码/素材/相机/配置会使旧证据失效。正式资产和 HD-2D 晋升继续使用对应工具的原有门槛。

## 可直接使用的离线命令

使用可用 Python3；工具仅依赖标准库。从仓库根目录运行：

```powershell
# 冻结样板是否仍与当前源码、资源及证据一致
python Tools/OCCVfx/occ_vfx_pipeline.py verify-lock

# 建立新配方；新文件是DRAFT，含纸板/柱/粒子分层蓝图，尚未填时长/尺度，也没有实机证据
python Tools/OCCVfx/occ_vfx_pipeline.py new fire_spell_02 --output Tools/OCCVfx/recipes/fire_spell_02.json

# 多项一起检查；每项独立返回错误，批次内ID不能重复
python Tools/OCCVfx/occ_vfx_pipeline.py check Tools/OCCVfx/recipes/sky_furnace_v1.json --stage design
python Tools/OCCVfx/occ_vfx_pipeline.py check Tools/OCCVfx/recipes/sky_furnace_v1.json --stage runtime
```

`new`拒绝覆盖已有文件；留空草稿会在设计检查中报缺口。`check --stage runtime`要求配方指纹、正常播放/回收、几何、双分辨率、视频及原生逐像素运动证据。目前落地的回读适配器是 `sky_furnace_fragment_readback_v1`；新效果要产生对应回读或实现自己的适配器，未知适配器直接报错，不静默放行。新配方不能靠复制旧证据得到实机 PASS。人工审美与正式晋升始终独立于这些技术检查。
