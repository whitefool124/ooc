# 魔法战争人生战棋肉鸽技术规划

## 文档状态

- 状态：暂定技术基线，实施前可修订
- 目标平台：PC（Windows 优先）
- 表现形式：像素风 2D
- 引擎建议：Unity 6 LTS + C#

## 一、技术目标

本项目的第一技术目标不是制作完整两小时单局，而是尽快验证以下体验是否成立：

1. 单主角对多敌人的速度条战棋是否足够紧凑。
2. 三行动点、朝向、掩体、伤害类型与任务目标能否形成稳定的确定性推演。
3. 战术重开能否可靠恢复至同一场战斗初始状态，让玩家寻找更优解而不是刷概率。
4. 装备、技能、消耗品和背包运营能否以数据驱动方式快速扩充。

## 二、技术选型

| 层面 | 选择 | 原因 |
| --- | --- | --- |
| 引擎 | Unity 6 LTS | 适合 2D、UI、C# 数据驱动与后续内容扩展；PC 工具链成熟 |
| 语言 | C# | 与 Unity 原生工作流一致，适合战斗状态与配置对象 |
| 渲染 | URP 2D Renderer | 像素地图、灯光、特效与后处理可控 |
| 输入 | Unity Input System | 支持鼠标键盘，后续可添加手柄 |
| UI | UI Toolkit 为管理界面，uGUI 或 UI Toolkit 为战斗 HUD | 战斗格子交互优先可控，背包和运营界面适合结构化 UI |
| 数据配置 | ScriptableObject + JSON 导出/导入 | 初期编辑效率高，后期可验证、版本化和批量平衡 |
| 存档 | JSON 存档 + 版本迁移字段 | 支持局外档案、战区进度和战斗重开快照 |
| 测试 | Unity Test Framework | 用 EditMode 测试战斗公式，用 PlayMode 测试流程 |

## 三、架构原则

### 3.1 战斗模拟与表现分离

战斗规则必须独立于 Unity GameObject 与动画表现。

- `CombatState`：纯 C# 状态，保存单位、格子、行动条、目标、物品和效果。
- `CombatCommand`：玩家或 AI 发出的单一意图，例如移动、攻击、施术、使用物品、互动。
- `CombatResolver`：验证命令合法性，执行确定性结算，生成状态变化与事件。
- `CombatEvent`：供地图、动画、音效、UI 消费的只读结果，例如移动、伤害、掩体破坏、状态施加。
- `CombatPresenter`：Unity 表现层，只播放事件，不能自行改写规则状态。

收益：同一份状态可以用于 SL 恢复、自动测试、战斗回放、敌人意图预览和未来的存档兼容。

### 3.2 确定性规则

- 命中、伤害、状态、格挡、抗性、行动条推进均不得使用运行时概率。
- 地图变体、敌人编成、奖励三选一、旅途事件可使用局内种子生成；种子写入单局存档。
- 每场战斗开始时保存 `CombatStartSnapshot`。SL 直接载入该快照，而不是重新随机生成地图或敌人。
- 所有敌人意图、延时动作和场地触发条件在状态层可计算并公开给 UI。

### 3.3 数据驱动内容

下列内容全部以配置数据定义，不在单位脚本中硬编码：

- 单位原型、敌人 AI 行为表、首领阶段。
- 武器、导具、防具、模块、消耗品、背包物品尺寸。
- 技能、状态、伤害类型、护甲/护盾/格挡公式参数。
- 地图模板、任务目标、地点、战区事件和奖励池。
- 出身、元素天赋、训练资格、人生事件与遗物记录。

## 四、核心系统拆分

### 4.1 格子与地图

- 二维方格坐标，包含阻挡、轻/重掩体、耐久、可破坏、可互动、危险区域和任务标签。
- 不实现高度、攀爬、多层建筑或战斗迷雾。
- 地图模板由手工设计的固定任务地图加变体插槽组成；变体只替换敌人出生、掩体、容器、奖励和附加条件。

### 4.2 行动条与行动点

- 每单位独立处于行动条中；主角每次行动固定获得 3 行动点。
- 移动、攻击、施术、道具、互动、原地转向均作为命令处理。
- 基础动作不推迟下一次行动；标记为“延时”的蓄力、重武器与强术式修改行动条时机。
- 每个敌人显示下次行动意图和关联目标格。

### 4.3 确定性伤害

建议结算顺序：

```text
基础伤害
-> 朝向固定修正
-> 技能/状态固定修正
-> 掩体固定减伤与耐久损失
-> 护甲 / 护盾 / 格挡结算
-> 伤害类型抗性或弱点
-> 生命与状态变化
```

普通敌人使用固定抗性与阈值；精英和首领可配置有限的百分比抗性。每一步必须能在战斗日志和悬浮说明中解释。

### 4.4 物品、装备和背包

- 深度装备槽：主副武器、分部位防具、背包、核心、导具、工具、能源、义体、饰品和 8 个快捷消耗品位。
- 格子背包：物品数据包含宽、高、堆叠、重量、以太负荷、快捷使用规则和容器属性。
- 战斗内只能立即使用快捷栏物品；翻找背包与临时换装消耗行动点。
- 关键容器搜刮使用 1 点行动点，物品立即进入背包；空间不足时必须当场处理。

### 4.5 战区与单局

- 少年序章 + 四个战区。
- 战区地图按天数/时段推进，区域逐步发现；战斗地图保持全图公开。
- 地点、旅行事件、时间、主目标和硬期限均保存为 `CampaignState`。
- 任务完成后由奖励服务产出保底资源与三选一奖励；战后工坊可免费重置技能与改装配置。

### 4.6 存档与恢复

存档分三类：

| 存档 | 内容 | 写入时机 |
| --- | --- | --- |
| 局外档案 | 编年史、永久资源、传闻 | 人生结算 |
| 单局存档 | 角色、背包、战区地图、时间、任务进度、随机种子 | 每次地点结算、进入战斗前 |
| 战斗快照 | 完整 `CombatState`、行动日志索引 | 战斗开始；用于 SL |

所有存档对象携带 `saveVersion`。每次数据结构修改时提供迁移或明确拒绝旧版本的策略。

## 五、最小可玩原型

### 原型范围

只做一张 16 x 16 至 24 x 24 的手工战棋地图：

- 1 名主角，3 至 5 名敌人。
- 3 行动点、独立行动条、敌人意图、朝向、轻/重掩体、可破坏物。
- 1 个破坏或撤离任务目标。
- 1 把普通武器、2 个主动技能、2 个消耗品、1 个容器搜刮点。
- 确定性伤害、战斗日志和 SL。

### 原型验收标准

1. 同一快照 SL 后，敌人位置、行动顺序、伤害、状态与地图耐久完全一致。
2. 玩家可在 5 至 8 分钟完成任务，并在不同路线中做出明确取舍。
3. 每一次伤害都能从 UI 看懂来源和减伤结果。
4. 掩体破坏、朝向、行动条与任务目标至少各改变一次最优决策。
5. 无概率命中、暴击或隐藏 AI 随机行为。

## 六、风险与防线

| 风险 | 后果 | 防线 |
| --- | --- | --- |
| 过早制作四阶段战役与大量内容 | 原型不成立时返工巨大 | 先完成单图垂直切片 |
| 规则散落在 MonoBehaviour | 无法可靠 SL、测试和回放 | 纯 C# 战斗状态与命令结算 |
| 深度背包压垮战斗节奏 | 5–8 分钟目标失效 | 只让关键搜刮进入战斗内；常规资源战后结算 |
| 伤害类型过多 | UI 难读、配置爆炸 | 首发只启用少数物理/元素类型，其他按内容逐步开放 |
| 像素资产制作拖慢开发 | 系统验证延后 | 原型阶段先用清晰色块、图标和占位动画 |
