# OCC 单位像素美术规范 v0.1

**状态：执行中。** 本规范约束剧情模式与肉鸽模式共用的战斗单位静帧原料、规范化输出和后续独立动画帧；它是角色三层视觉中的 A 层（战棋形象），并补充《OCC 美术规范 v0.1》《OCC 角色三层视觉规范 v0.1》与《OCC 像素资产 QA 流程 v0.1》。

## 1. 交付边界

- 正式单位首先只交付一张独立 `64×64` 静帧。待机、受击等运行时表现优先使用整数像素位移、色彩/亮度脉冲，不得用同一张图伪造动画。
- 每张原料必须独立生成或绘制；禁止从 AI 拼板、角色海报、地图或其他项目资产中裁切。
- Codex 生成图只作为原料：保留原图、去背中间文件、规范化 PNG、4× QA、调色板与 JSON 报告。通过 QA 后才可标为 `FORMAL`；导入 Unity 另行评审。
- 本批不要求高保真手工重绘，但必须满足“规格正确、轮廓可读、表面语义明确”。

## 2. 固定画布与锚点

| 项目 | 规范 | 验收容差 |
| --- | --- | --- |
| 画布 | RGBA `64×64`，单单位、完整可见 | 不允许裁边或多角色 |
| 中心线 | 单位重心围绕 `X=32` | 主体视觉重心在 `X=29–35`；持枪/盾牌可越出但不得失衡 |
| 脚底基线 | 站立接地以 `Y=58` 为准 | 接地点允许 `Y=57–59`；不得悬空或超过 `Y=59` |
| 标准单位有效高度 | 主体轮廓约 `32–38 px`，脚底基线不变 | 长枪、盾沿或导具可局部延伸至约 `44 px`，但不得形成连续遮挡墙 |
| 精英/首领有效高度 | 主体轮廓约 `38–44 px`，以体量区别普通单位 | 特殊设备可超出，但头肩、脚底和相邻格目标必须仍可读 |
| 透明边界 | 四角透明、硬 alpha | 只允许 `0/255` alpha；无绿幕漏色、光晕或投影 |
| 有效轮廓 | 预留足够外缘以读清武器和姿态 | 标准主体建议约 `X=16–48`、`Y=20–59`；武器/盾具超出须在报告说明 |
| 缩放 | 最近邻、整数倍 | 禁用抗锯齿、平滑、非整数缩放 |

> 2026-08-07 体量修正：相对既有接触表，单位平均视觉轮廓缩小约 30%，但 `64×64` 画布、`X=32` 和 `Y=58` 不变。正式资产必须在原生逻辑像素中按上述较小轮廓绘制或人工清理；禁止在 Unity 中把旧图直接设为 `0.7` 非整数缩放。脚本缩放只可用于接触表审查预览，不可作为正式单位交付物。

## 3. 视角、姿态与可读性

- 使用与当前正交战棋相容的**近顶视三分之四角**：头肩、躯干、脚底和主武器都能读出，不能做正侧视、透视立绘或伪等距立绘。
- 默认面向右下（屏幕东南）；未来朝向变体沿相同中心线、脚底基线和武器起点镜像/重绘，不能改变占格。
- 单位在 1× 时应先读到阵营、兵种和战斗姿态；4× 时才读取线缆、护甲层次和以太装置。任何文字、徽章字母或细碎仪表均不可作为识别信息。
- 阴影如需要，只能是紧贴脚底的 1–2 像素深色接地形，不得延伸成软边投影或遮住格位。

## 4. 阵营与色彩预算

| 组成 | 主色与预算 | 禁止项 |
| --- | --- | --- |
| 中性结构 | 煤灰、铁黑、混凝土灰；约 70–85% 可见面积 | 大面积高饱和金属、纯白外壳 |
| 友方/通用以太 | 冷青只用于肩章、回路、导具或选定线缆；约 5–15% | 用冷青填满整件制服或皮肤 |
| 敌方威胁 | 氧化红用于识别带、武器发热区或护甲边缘；约 5–15% | 与冷青共同成为大面积主色 |
| 交互/装备提示 | 安全黄橙仅为锁扣、弹药/医疗标记或小型警示；不超过 5% | 取代敌我阵营主色 |
| 调色板 | 静帧最多 24 个可见 RGB 色 | 抖动、渐变、半透明烟雾或未定义发光色 |

## 5. 兵种轮廓合同

| 类型 | 1× 必须可读的主特征 | 禁止混淆 |
| --- | --- | --- |
| 主角/游击者 | 单手武器或步枪、轻型战术外套、小型以太导具 | 不得像重甲盾卫或披袍术师 |
| 步枪兵 | 一支长而直的步枪，枪口朝向明确 | 不得以短枪或法杖替代 |
| 盾卫 | 身体一侧的大宽盾，护甲体量更厚 | 盾牌不能小到像手枪或背包 |
| 术师/净化者 | 导具、导管/线缆和受控以太组件 | 不得使用法袍、圣光、漂浮符文等中世纪语汇 |
| 突袭者 | 轻装、短枪/短刃、前倾机动姿态 | 不得与步枪兵的长枪轮廓相同 |
| 精英/首领 | 更大体块、加固护甲、额外能源模块或独特主武器 | 不能仅把普通兵换成更亮颜色 |

## 6. Codex 单图原料提示词模板

```text
Asset type: one independent 64×64 OCC tactical-unit source image; not a sprite sheet.
Subject: <兵种、主特征、装备与阵营>.
View: near-top-down three-quarter tactical view, facing screen lower-right; full body visible.
Pixel contract: native logical 64×64 pixel grid, limited 24-color palette, hard-edged pixel clusters, no anti-aliasing.
Anchor contract: body centered around X=32; feet touch logical Y=58; standard visible body silhouette about 32–38 logical pixels tall with generous transparent margin; weapon tips may extend to about 44 pixels.
Backdrop: perfectly flat #00ff00 chroma-key background; no floor, cast shadow, reflection, text, logo, UI or watermark.
OCC language: modern industrial arcane warfare; aether shown only as maintainable conduits, coils or tools.
Avoid: medieval robes, holy glow, floating runes, painterly blur, extra characters, sprite sheets.
```

## 7. 人物静帧 QA 门禁

1. **来源：** 原图是单人单图，文件名、生成提示词和使用范围可追溯。
2. **规格：** `64×64`、硬 alpha、最多 24 色；标准单位主体高度约 `32–38 px`，精英/首领约 `38–44 px`；正式输出禁止运行时非整数缩放、自动裁切拟合或破坏锚点的重定位。
3. **锚点：** 4× QA 图叠加 `X=32` 与 `Y=58`，记录边界与接地点。
4. **轮廓：** 在 1×、4×、灰阶和透明棋盘格背景中检查；兵种的主特征必须保留。
5. **语义：** 确认为近代魔导工业语汇，且友方冷青、敌对氧化红、安全黄橙的局部使用不冲突。
6. **批准：** 原料、规范化 PNG、4× QA、调色板、JSON 报告与审查结论齐全后可升为 `FORMAL`；Unity 导入再检查 Sprite、Point、Clamp、无 mipmap 与整数缩放。

## 8. 首批执行顺序

1. 用本规范复核现有 `hero`、`rifleman`、`shieldguard`、`pyromancer`、`raider` 与 `elite` 的原料证据。
2. 新增人物时优先补齐尚无独立原料或兵种轮廓不清的单位，不以重复生成已有兵种为目标。
3. 动画仅在相关静帧 `FORMAL` 后再立项；每帧沿同一 `X=32` / `Y=58` 规范单独 QA。
