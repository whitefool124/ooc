# OCC 美术规范 v0.1

**状态：暂定。** 本规范用于约束原型后的像素资产、地图、单位、UI 与特效制作；不替代玩法信息层级。

## 1. 核心方向

定位为 **近代工业魔导战术像素风**：铁路、工厂、军用器材、以太回路、战场残骸共同构成场景。魔法表现必须能读出能源、导体或回路，不使用中世纪法袍、神圣金光或无来源的漂浮魔法。

世界观约束：以太素是唯一超凡来源；视觉语言应体现可维护、可损坏、可污染的能量工程，而非许愿式奇幻。

## 2. 技术与比例

- 战斗地图使用正交 2D 方格，1 格的源像素尺寸固定为 `32×32`。
- 单位占 1 格；人物源精灵建议 `48×64` 或 `64×64`，脚底锚点对齐格子中心。
- 所有游戏内像素图按整数倍缩放；禁用抗锯齿、模糊与非整数缩放。
- 正式战斗镜头不采用伪等距或透视格子。若使用概念图中的倾斜视角，只能作为氛围参考，不能直接决定可走格与掩体轮廓。
- 中文 UI 正文优先使用清晰的黑体类字体；像素中文标题需另行制作，不能以难读的 AI 伪字替代。

## 3. 颜色语义

| 用途 | 建议色 | 规则 |
| --- | --- | --- |
| 地面/背景 | 煤灰、铁黑、混凝土灰 | 大面积低饱和，保证单位与交互突出 |
| 友方/通用以太 | 冷青 | 用于移动、回路、常规能量 |
| 敌对威胁/伤害 | 氧化红 | 用于敌人、危险火力、损伤 |
| 交互/战利品 | 安全黄橙 | 用于目标、搜刮、提示 |
| 治疗/护盾 | 灰绿 | 不与移动青混用 |
| 污染/高风险术式 | 暗紫红 | 仅用于异常与污染 |

高饱和冷青只能作为局部导管、射线和交互点，不能铺满地面或 UI。

### 角色三层视觉（2026-08-02）

- 每名角色按用途拆分为：`64×64` 战棋形象、角色立绘形象和能够读取表情细节的演出形象。
- 三层共享体态/年龄、头部特征、职业装备、服装结构、阵营/个人色与以太技术语言；它们是同一角色的不同镜头距离，不能各自重新设计。
- 战棋形象优先服务职业、阵营和占格；立绘服务身份、服装与装备；演出形象优先服务眼神、眉眼与嘴部表情。
- 演出形象保持像素风与受控调色板，可使用比战棋单位更高的细节密度，但不使用柔焦、写实皮肤、平滑渐变或 AI 伪文字。
- 具体锚点、提示词、表情集与 QA 门禁见 `OCC_角色三层视觉规范_v0.1.md`。

### 战术 HUD 视觉规则（2026-07-22）

- 战斗 HUD 定位为 **极简工业仪表界面**：以黑、近黑、暖白/冷白为大面积基底，使用充分留白、细分隔线与严格对齐建立层级；不使用厚重金属板、铆钉、浮雕边框、斜切装甲框或高密度机械装饰。
- 框架只使用 1--2 px 等效的直线、短角标与必要的细边界；卡片由底色明度差和留白区分，不能依赖大面积描边或阴影。
- 图标为独立制作并 QA 的像素风图标：法术、法宝、物品、导航与战斗效果仍使用 `32×32` 图标格；`行动 / 以太 / 注意` 三枚常驻语义微图标及敌人头顶常驻意图图标使用 `16×16` 源图，在 1920×1080 至少以 1×整数显示。微图标最多四种实体色、轮廓清楚，不使用复杂物件、材质细节或 AI 图中的文字；伤害数值由 UI 实时叠加，不烘焙进图标。
- 背包多格物品另备独立占格素材：源画布严格为 `物品宽×32` × `物品高×32`，与 `1×1 / 2×1 / 1×2 / 2×2 / 3×2 / 1×3` 等目录尺寸一致。HUD、快捷栏和奖励的内容图标仍使用 `32×32`；`action/aether/notice` 语义词汇和敌人头顶意图使用 `16×16` 源图。背包不得把语义图标非等比拉伸填满多格。占格素材保持透明硬 Alpha、有限色板、Point、Clamp、PPU32 与整数像素边界；16×16 微图标使用 PPU16。
- 色彩配比以黑白/灰阶为主。冷青仅表示可执行操作、友方以太和选中；锈红仅表示敌对威胁/伤害；安全黄橙仅表示交互/战利品；单屏高饱和色面积应显著小于中性色面积。
- 中文正文使用清晰黑体，标题可使用字重和字距区分；不得以像素中文或 AI 伪字承担信息阅读。

### 低像素物品图标基准（2026-08-13，已锁定）

- **适用范围：** 背包、快捷栏、奖励与法宝/消耗品的 `32×32` 内容图标；它们是物品阅读，不是地图节点语义图标，也不是战棋场景物件。
- **逻辑分辨率：** 先在独立的 `16×16` 逻辑画布上绘制，再以最近邻整数 `2×` 放大为 `32×32` PNG；不得把高分辨率概念图缩小后伪装为低像素画。所有主要轮廓边、材质分区和功能色块必须落在 `2×2` 像素块上。
- **形体预算：** 每件物品只保留一个主轮廓、两个至三个结构分区，以及一个功能识别点。优先让玩家读出类别而非制造细节；禁止细小螺丝、划痕、线缆、文字、环境光、投影、玻璃反光和微型材质纹理。
- **描边与色彩：** 使用近黑轮廓封住物体；中性煤灰/铁灰承担主体；冷青仅用于以太或受控电力，安全黄仅用于交互、维护或战利品语义，橙/锈红仅用于热量、火险或敌对危险。单件通常不超过 5--6 个实体色，且不使用渐变、柔光、抗锯齿或半透明阴影。
- **构图：** 物体在 `16×16` 画布中留出至少 1 个逻辑像素的透明安全边；正视或严格侧视，禁止透视。若道具需要方向性，使用大形体而不是细小箭头或局部高光表达。
- **固定样本：** `Worldbuilding/05_美术与音频/像素资产原料/V2-23/新美术指导规格样本/Items32/occ_fire_canister_v04.png`、`occ_grid_disposer_v04.png`、`occ_recon_beacon_v04.png` 为本条的视觉密度、描边和色彩基准；它们为美术样本，未经逐项内容验收不得自动作为 Unity 正式资产。
- **QA：** 输出必须为 `32×32`、硬 Alpha、最近邻整数缩放和受限色板；审查时先以原始 `32×32` 尺寸判断轮廓和类别，再以 4× 网格图检查是否存在单像素噪点或非整数边缘。

### 原生 32×32 物品图标方向（2026-08-13，已锁定）

- **层级：** 这是与上方“低像素物品图标基准”并列的原生 `32×32` 物品层，不是把 `16×16` 图标缩放或降采样而来的版本；适用于需要保留基础材质识别的拾取物、消耗品和材料。
- **画面规则：** 深炭黑 `1px` 外轮廓，主体约占 `20–26px`，四周至少留 `2px` 空隙；使用 `4–6` 个平涂色阶，不使用渐变、抗锯齿、柔焦、环境光或投影。
- **材质线索：** 每件物品只保留一个可读材质结构。金币使用偏移硬币边缘与中央压印；木酒杯使用深色杯口、竖向木板分段和方折把手；面包使用低矮横向轮廓、深色底壳及两道斜割纹。材质必须服务轮廓，不能以碎纹理堆砌。
- **固定提示词骨架：** `native 32x32 pixel grid, hard 1px near-black outline, 4 to 6 flat colors, no anti-aliasing, no gradients, single centered game item, readable silhouette at 1x`，再追加该物品的轮廓与材质线索。

### 16×16 微型物品基准（2026-08-13，已锁定）

- `16×16` 是独立设计层，禁止直接缩放任一 `32×32` 物品；每件图标按 16 格的轮廓预算重新取舍。
- 主体宜控制在 `10–12px` 宽高、四周留约 `2px` 空隙；以约 `5–8` 个离散色（含近黑轮廓）构建材质。颜色角色按“轮廓、投影暗面、局部底色、中间调、受光面、点状高光、材质暗纹”取用，以连续的像素簇而非平面符号建立体积。
- 轮廓为粗实的近黑阶梯线；每件物品保留一个轮廓重心、至少一组清楚的体积明暗和一个明确材质结构（叶片分片、果实暖光核、硬币同心压印、木桶箍/杯口、面包斜割纹）。不使用渐变、抗锯齿、随机单像素噪点、文字、环境投影或缩小的高分辨率绘图。
- 验收顺序固定为：`1x 轮廓可认` → `放大后体积与材质可判` → `同组比例一致`。若必须靠细碎纹理解释类别，应重组大色块而不是继续添加细节。
- **固定视觉样本：** 用户确认的“草药、炽果、金币、木杯、面包”五物品参考图 `C:/Users/FNHF/AppData/Local/Temp/codex-clipboard-b1582f9e-e02f-45e4-9c25-28d142b8298b.png` 为本条唯一的轮廓粗细、材质密度和高光节奏基准。先前 `Items16/*_v03.png` 是被否决的符号化试验，只可保留作反例，不得作为后续提示词或正式资产依据；所有样本均尚未逐项内容验收或导入 Unity。

### 肉鸽地图节点图标（2026-08-13）

- 地图节点图标固定为独立 `16×16` 逻辑像素格，透明硬 Alpha、Point、Clamp、PPU16；地图 UI 只允许整数倍显示。只表达节点功能，不绘制地点、角色、完整道具或叙事插画。
- 每个图标只保留一个居中的简约符号，深色轮廓 + 1 个语义主色 + 至多 1 个中性填充色；总色数不超过 4 色，不使用渐变、投影、反光、材质纹理、透视、环境光或文字。
- 语义：普通战斗为交叉训练剑；精英为尖角徽记；事件为折角文书；工坊为扳手；商店为补给袋；休整为医疗十字；宝藏为锁匣；首领为封存尖塔。图标必须在 16×16 缩览下仍可按轮廓区分。
- 色彩仍服从 HUD 语义：冷青仅表示当前可执行/以太，锈红仅表示精英/首领威胁，安全黄仅表示商店/宝藏，灰绿仅表示休整；普通节点以灰白中性标识为主。不得以大量工业管线、机械结构或场景碎片替代图标轮廓。
- AI 生成只能作为原图来源；每个原图必须单独生成，并直接要求 `16×16` 逻辑像素风格，之后独立最近邻规范化、色数/硬 Alpha/边界 QA，并在 Unity 导入设置中复核。不得从一张拼板图硬切出正式图标。

## 4. 地图与单位

- 轻掩体必须低矮、可越视；重掩体必须更高、更厚且能明确读出阻挡。
- 可破坏物必须准备完整、受损、残骸三段状态。
- 每张战斗图有一个工业/军事叙事锚点，例如中继器、铁路货台、净化站、炮台或机库。
- 兵种依靠轮廓区分，而非只换颜色：步枪兵的长枪、盾卫的宽盾、术师的导具/线缆、精英的体量与复杂装备必须可读。
- 朝向由武器、身体和投影共同表现；状态特效不得遮住单位所在格。

### 64×64 战棋单位比例基准（2026-08-14，已锁定）

- **用途区分：** 角色档案/立绘可使用满画幅、大头部与高装备密度；战棋单位不得沿用该比例。战棋精灵的职责是格内辨识、朝向与状态阅读，而非展示角色全身细节。
- **占格预算：** 原生画布固定为 `64×64`；标准人形从头顶到靴底为约 `44–48px`（约占画布高 `70–75%`），常规躯干宽约 `32–38px`。四周须保留可见空隙，避免人物贴边、越格或挤占脚底状态信息。
- **对齐：** 靴底公共基线为 `Y=56`，角色中心线靠近 `X=32`；武器、披风与背负装备可以形成轮廓外扩，但不得在常态下越过画布边界。
- **头部与表情：** 头部约 `12–14px` 高，必须保留至少眼睛与眉/嘴中的一个表情信息；不得以封闭头盔、护目镜或浓重阴影完全遮住面部。表情优先于发丝、扣件和衣料碎纹。
- **造型层级：** 用头部、躯干、腿部、主武器/导具四个大形体阅读兵种；外套、背带、护膝、以太瓶等只保留少量像素簇。冷青仅用于可控以太/可交互能量，锈红用于敌方威胁，煤灰与棕色承担主体。
- **固定视觉样本：** `Worldbuilding/05_美术与音频/像素资产原料/V2-23/新美术指导规格样本/References/occ_tactical_unit_scale_v01.png` 为战棋单位的缩回比例、面部可见度、脚底对齐与色彩关系参考；它是概念样本，不得直接切图或导入 Unity。

## 6. 生成图使用规则

- AI 图只可用于风格板、色彩与材质参考，不能直接作为正式角色、图标、UI 文本或像素地图资产。
- 生成图出现的文字、符号、仪表读数一律视为不可用；正式版本须重绘。
- 正式资产先制作 1 张 `12×9` 正交地图切片、4 个单位、轻/重掩体和中继器，再扩展素材库。
- 特效优先使用 4–10 帧的低成本像素动画；命中停顿与信息可读性优先于复杂粒子。
