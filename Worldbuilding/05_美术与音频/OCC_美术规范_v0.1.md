## 1. 核心方向

定位为 **质朴西幻魔法侧的近代以太文明战术像素风**。世界仍有铁路、工厂与可维护的以太工程，但人物、单位、可携装备与学院空间优先读取布、皮、木、石、陶、锻铁和少量旧铜；结构应像工匠与学院长期使用、修补和传承的器物，而不是高科技外骨骼或科幻终端。魔法必须有符文、刻阵、媒介、药剂、法杖、护符或可见代价作为来源；允许朴素法袍、短斗篷与传统学院服，但禁止无来源的漂浮魔法、神圣万能光和纯装饰光污染。

> **2026-08-22 人物风格修订：** OCC 人物美术的主方向为“质朴、偏西幻魔法侧”。既有高工业化人物候选只可登记为备用，不得继续主导正式生产。人物身上禁止大面积机械装甲、外骨骼、密集管线、LED 式发光节点、科幻面罩、战术尼龙堆叠和电路板纹样；以太工程通过手工刻纹、缝线、金属箍、木石导具与少量低亮度晶体表达。

世界观约束：以太素是唯一超凡来源；视觉语言应体现可维护、可损坏、可污染的能量工程，而非许愿式奇幻。

## 2. 技术与比例

- 战斗地图使用正交 2D 方格，1 个逻辑格固定为 `32×32`。单格地块、掩体、设备与碰撞物使用原生 `32×32`；诚实占据 `W×H` 个逻辑格的场景物使用原生 `(W×32)×(H×32)` 透明画布，不得压回单格。大面积纯地板允许使用原生 `16×16` 逻辑像素稿最近邻 `2×` 输出到 `32×32`，以降低纹理密度。
- **应用环境优先：** 决定资产画布、有效轮廓、像素簇密度和透明留白前，必须先锁定它在实际界面的功能、逻辑占格、运行时绘制矩形、相邻单位／覆盖层、默认与最小分辨率。`32×32`／`64×64` 是由应用环境反推的交付合同，不是先画满画布再强行塞进界面。每份生产简报必须先写“应用环境与屏幕占位”，再写尺寸和绘制细节。
- **交付尺寸与细节密度分离：** 不以 `20×20`、`24×24` 等非合同尺寸拉伸填充战斗格来寻找中间密度。需要介于 16 与 32 逻辑像素之间的观感时，仍使用原生 `32×32` 交付，并通过较大的连续像素簇、低色数和留白控制密度。当前战斗格 `64/96/128/160` 对 `32×32` 资产严格对应 `2×/3×/4×/5×`；正式地块必须通过这四档整数缩放预览。
- 单位占 1 格；人物源精灵建议 `48×64` 或 `64×64`，脚底锚点对齐格子中心。
- 所有游戏内像素图按整数倍缩放；禁用抗锯齿、模糊与非整数缩放。
- 正式战斗镜头不采用伪等距或透视格子。若使用概念图中的倾斜视角，只能作为氛围参考，不能直接决定可走格与掩体轮廓。
- **战场建筑／道具投影门禁：** 地面保持严格正交俯视；具有高度的建筑片段、掩体、设施和容器统一使用战棋俯视 3/4 投影——顶面必须可见，前立面压短，接地点落在格内下半部，左右侧面缩短且不产生消失点。禁止把正面立视的书柜、塔、墙或箱体直接贴到俯视地面。每批必须先放入实际 `12×9` 战场，以当前运行时相机、单位和范围覆盖共同截图；单资产接触表只能作为辅助，不能代替实机视角验收。
- **当前学院战场绘制合同：** 32px 地面／物件使用完整逻辑格绘制矩形，透明边界控制有效轮廓，以保持 `64/96/128/160` 参考格下的 `2×/3×/4×/5×`；不得用运行时统一 inset 把它变成 1.75×、2.625×、3.5× 等非整数倍率。64px 单位在默认 128px 格使用严格 2×，在中间缩放档向上量化到 64px 整数倍并以脚底／画布下沿锚定，表现可以越格但逻辑命中格不变。
- 中文 UI 正文优先使用清晰的黑体类字体；像素中文标题需另行制作，不能以难读的 AI 伪字替代。

## 3. 颜色语义

| 用途 | 建议色 | 规则 |
| --- | --- | --- |
| 地面/背景 | 煤灰、铁黑、混凝土灰 | 大面积低饱和，保证单位与交互突出 |
| 友方/通用以太 | 冷青 | 用于移动、回路、常规能量 |
| 敌对威胁/伤害 | 氧化红 | 用于敌人、危险火力、损伤 |
| 交互/战利品 | 安全黄橙 | 用于目标、搜刮、提示 |
| 治疗/护盾 | 灰绿 | 不与移动青混用 |
| 污染/高风险术式 | 暗紫红 | 仅用于异常与污染 |

高饱和冷青只能作为局部导管、射线和交互点，不能铺满地面或 UI。

### 角色三层视觉（2026-08-02）

- 每名角色按用途拆分为：`64×64` 战棋形象、角色立绘形象和能够读取表情细节的演出形象。
- 三层共享体态/年龄、头部特征、职业装备、服装结构、阵营/个人色与以太技术语言；它们是同一角色的不同镜头距离，不能各自重新设计。
- 战棋形象优先服务职业、阵营和占格；立绘服务身份、服装与装备；演出形象优先服务眼神、眉眼与嘴部表情。
- 演出形象保持像素风与受控调色板，可使用比战棋单位更高的细节密度，但不使用柔焦、写实皮肤、平滑渐变或 AI 伪文字。
- 具体锚点、提示词、表情集与 QA 门禁见 `OCC_角色三层视觉规范_v0.1.md`。

### 战术 HUD 视觉规则（2026-07-22）

> **2026-08-19 主题修订：** 原“黑、近黑、暖白／冷白为大面积基底”仅保留为历史结构原则，不再是现行配色基线。剧情／肉鸽共用 UI 已改为“学院档案与实地调查手册”：暖纸白、石灰、档案卡和炭墨构成大面积层级，深色只用于页脊、遮罩与少量承重托盘；冷青只表示主动以太、选中或可执行状态。常规页面禁止扫描线、终端网格、冰蓝普通描边和系统接入式装饰。完整色值、材质和验收见 `OCC_UI学院档案视觉规范_v0.1.md`。

- 战斗 HUD 定位为 **学院档案式战术记录界面**：以暖纸白、档案卡、炭墨和少量深色承重托盘建立层级，使用充分留白、细分隔线与严格对齐；不使用厚重金属板、铆钉、浮雕边框、斜切装甲框或高密度机械装饰。
- **历史规则已被 2026-08-19 学院档案像素框合同取代：** 原 `1--2 px` 细线不再用于主要容器。主卡片、按钮、槽位和弹层使用 `6 px` 外框／`12×12 px` 方角块；细分隔线仍可使用 `2 px`。卡片同时依靠底色明度差与留白区分，禁止退回金属装甲框或大面积阴影。
- 图标必须独立制作并 QA：`16×16` 仅用于行动、以太、注意、敌人意图和地图节点等**语义符号**；`24×24` 用于食物、植物、果实、金币、瓶罐等需要材质阅读的拾取物原生源图；`32×32` 用于法术、法宝、装备、单格地图地块与单格场景物；`64×64` 用于战棋单位。多格场景物与背包占格素材按逻辑格公式扩展，不属于新的像素密度层。伤害数值由 UI 实时叠加，不烘焙进图标。
- 背包与 HUD 槽位可以是 `32×32`，但材质型拾取物保留原生 `24×24` 源图，并以 `(4,4)` 不缩放居中到 `32×32` UI 交付画布；不得放大为伪32像素画，亦不得非等比拉伸填格。背包多格物品另备独立占格素材：源画布严格为 `(物品宽×32)×(物品高×32)`，与 `1×1 / 2×1 / 1×2 / 2×2 / 3×2 / 1×3` 等目录尺寸一致。Unity 只导入交付画布：16px语义图使用 PPU16，其余当前32px格体系的UI、地图、64px单位与多格素材统一使用 PPU32；24px原生拾取物作为可追溯源稿保留，不以 PPU24 直接进入当前正式槽位。
- 色彩配比以黑白/灰阶为主。冷青仅表示可执行操作、友方以太和选中；锈红仅表示敌对威胁/伤害；安全黄橙仅表示交互/战利品；单屏高饱和色面积应显著小于中性色面积。
- 中文正文使用清晰黑体，标题可使用字重和字距区分；不得以像素中文或 AI 伪字承担信息阅读。

### 像素资产尺寸与阅读层级（2026-08-20，已锁定）

- **16×16 语义层：** 只表达功能，不画完整物件。深色轮廓 + 1 个语义主色 + 至多 1 个中性色，总色数不超过 4；不使用材质纹理、透视、环境光或文字。
- **24×24 材质拾取物层：** 食物、植物、果实、货币、瓶罐等以“粗近黑阶梯轮廓 + 连续明暗像素簇 + 一个材质结构”阅读。使用约 5--8 个离散色，保留 `1px` 透明安全边；禁止四色 UI glyph、渐变、抗锯齿、随机噪点与把高分辨率插画缩小充数。
- **32×32 装备/地块交付层：** 装备、法宝、法术、单格地块和单格场景物保持 `32×32` 交付画布。多格场景物按 `(W×32)×(H×32)` 原生构造并登记逻辑占格，不得缩入32px。大面积无碰撞纯地板可采用 `16×16` 逻辑像素稿最近邻 `2×` 交付，以匹配整体粗像素密度；装备、掩体、设备、法术和具有碰撞／高度／状态信息的场景物须以其真实交付画布原生构造。该地板例外不得覆盖24×24材质拾取物规则。
- **64×64 单位层：** 采用下方“64×64 战棋单位比例基准”；人物、单位与大特效必须独立制作，不从概念拼板硬切。全单位接触表必须统一原生像素密度、头部尺度与脚底基线。

## 6. 生成图使用规则

- **脚本几何不得充当正式像素美术：** 生产或 QA 脚本可以执行去背、定尺寸、最近邻缩放、硬 Alpha、色板限制、接触表和报告输出，但不得用矩形、直线、椭圆或预制部件拼出人物、掩体、建筑、设施、容器和场景道具后登记为 `FORMAL`。机械门禁通过只代表技术规格合格，不代表美术放行。

- **禁止使用本地生图工作台：** OCC 后续美术任务不得启动、调用或依赖本机图片中转／生成工作台、localhost 生图 API、私有 relay 服务或其批量生成脚本。不得在直接生成渠道失败后自动回退到本地工作台。
- 允许的正式生产来源仅为：项目当前明确批准的直接图像生成能力，或 PixelOver／Aseprite 等人工像素制作工具。渠道发生变化时必须先更新本规范，不得由执行者自行增加替代服务。
- 既有位于本地图片生成目录的历史参考图只保留其已经登记的审计角色，不因此获得正式资产资格，也不得作为继续调用该工作台的先例。
- AI 图可作为可追溯的独立原料或概念参考，但绝不能把生成输出直接登记为正式角色、图标、UI文本或像素地图资产。原料必须保留来源、提示词、哈希，经整轮廓规范化／人工像素清理、机器 QA、应用接触和人工审美批准后，规范化产物才可进入正式候选；生成图中的文字与伪符号永远不可转正。
- 生成图出现的文字、符号、仪表读数一律视为不可用；正式版本须重绘。
- 正式资产先制作 1 张 `12×9` 正交地图切片、4 个单位、轻/重掩体和中继器，再扩展素材库。
- 特效优先使用 4–10 帧的低成本像素动画；命中停顿与信息可读性优先于复杂粒子。
