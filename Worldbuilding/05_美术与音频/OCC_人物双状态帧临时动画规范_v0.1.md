# OCC 人物双状态帧临时动画规范 v0.1

> 状态：ACTIVE TEMPORARY / SUBORDINATE（2026-08-23）。适用于 OCC 全项目所有人物、角色、战斗单位与具备角色身份的生物／构造体动画美术，不区分剧情／肉鸽模式、玩家／敌方／中立阵营或地区。该规范用高一致性的离散状态帧与受控整数像素位移表达动作，不把脚本部件补帧、骨骼插值或运行时绘制伪装成正式逐帧动画；来源、风格、尺寸和状态晋级服从 `OCC_美术规范_v0.1.md` 唯一合同。

### 适用范围

- 包含：主角、可命名角色、普通敌人、精英、首领、NPC、学生、教职人员、役兽、召唤物、拟人构造体及其他需要保持角色身份的活动单位。
- 覆盖角色三层视觉：A 层战棋形象、B 层角色立绘形象、C 层演出形象。三层沿用各自画布与锚点，只共享双端点和身份一致性原则。
- 不包含：纯地块、掩体、设施、无角色身份的可破坏物、独立环境动画、纯 VFX、UI 动效与镜头动画；这些资产继续服从各自规范。
- 若某个资产同时包含人物与特效，人物主体必须服从本规范；可分离的能量、烟尘、命中和环境层必须作为独立 VFX 生产。

## 1. 使用目的

当前角色逐帧生产无法同时稳定满足身份、服装、比例、轮廓、装备与锚点一致性。OCC 全项目人物动画暂时不追求连续形变；每项人物动作只生产两个能够独立通过正式像素 QA 的动作端点：

- frame_00：预备／蓄势状态。角色仍能一眼识别，重心开始变化，但动作尚未命中。
- frame_05：动作峰值／完成状态。主装备、施术手或扑击方向明确，不能仅靠特效说明动作。

A 层战棋单位的常态待机继续读取正式单位身份静帧；B／C 层继续读取各自正式常态立绘／演出帧。运行时动作开始后在两个端点间硬切换，结束后返回常态；力度由人物图层的整数像素位移、短促抖动、色闪和独立 VFX 表达。

## 2. 玩家阅读目标

玩家在一秒内必须先认出“哪个单位在行动”，再认出“近战、施术、扑击或受击的方向”。状态切换不得改变身份、体型、服装、主装备、阵营色或面朝方向。

所有角色继续服从其地区、年代、阵营与职业的现行设定；人物主风格统一为质朴、偏西幻魔法侧，超凡表现必须通过符文、刻阵、法杖、符册、药剂、护符或其他手工媒介读出可维护、有来源的以太工程。冷青只表示少量主动以太，锈红只表示敌对／威胁；禁止在端点中新增机械外骨骼、LED 节点、科幻面罩或密集线缆。不得为了复用动作端点而抹平地区、年龄、种族、职业、装备或个人身份差异。

## 3. 两帧资产合同

以下 64×64 数值用于 A 层战棋单位。B 层立绘与 C 层演出形象沿用《OCC 角色三层视觉规范 v0.1》的原生画布、构图与锚点，但同样必须独立生产两个端点、保持身份一致、使用硬边像素并通过 1×／目标显示尺寸审查。

- 单帧原生 64×64，硬 Alpha、Point、Clamp、PPU32、无 mipmap、无压缩。
- 中心近 X=32，脚底基线 Y=56–59；两帧脚底差不超过 1px，整体中心差不超过 2px。
- 头、躯干、腿、主装备是四个主要质量块；头部与主装备在两帧中不得换形、换手、变色或改变尺寸。
- 身高、肩宽、头身比与待机静帧差异不超过 2px；允许动作侧肢或武器进入安全边界，但不得裁切。
- 两帧必须分别独立生产或手工清理；同一待机图平移、旋转、拉伸、换色或拼接矩形部件不算新状态。
- 双端点不得通过本地生图工作台、localhost 生图 API 或私有 relay 生产。允许来源仅为全局美术规范批准的直接生成渠道，或 PixelOver／Aseprite 人工制作；生成渠道失败时不得自动回退。
- 新人物动画资产统一只登记两个端点；序列式路径使用 frame_00／frame_05。既有系统若使用语义状态名，资产清单必须明确映射到 start／end 两个端点。
- 不要求 frame_01–04。这些文件若存在，只能作为旧 REWORK 审计证据，不得由运行时加载，也不得写入正式资产数量。

## 4. 运行时表现合同

- 0%–49% 显示 frame_00，50%–100% 显示 frame_05；动作结束立即返回正式待机静帧。
- 切换必须是硬切，不做纹理混合、骨骼插值、网格变形、运行时补画或运动模糊。
- 抖动只作用于人物图层位置并使用整数像素偏移。A 层普通动作最大 1px，重击／受击最大 2px；B／C 层必须按显示倍率换算为相同视觉幅度，不得按大画布比例放大抖动。
- 抖动仅位于动作中段，最多四次正负交替；不得持续随机噪动，不得改变逻辑坐标、碰撞、命中或镜头。
- 用户将动画强度设为 0 时，状态帧切换与抖动均停用；关闭“屏幕震动”只关闭受击额外抖动，不影响必要的动作状态阅读。
- 位移、色闪、意图图标和 VFX 都是表现层，不得成为隐藏战斗信息或修改实际结算时序。

## 5. 动作方向

| 类型 | frame_00 | frame_05 | 局部表现 |
| --- | --- | --- | --- |
| 近战／重击 | 重心后收、武器蓄势 | 武器到达清晰命中方向 | 朝目标短促推进；峰值 1–2px 交替抖动 |
| 远程／施术 | 手杖、弩或灯具抬起 | 发射／刻阵手势完成 | 轻微上提；冷青只出现在有效回路 |
| 四足扑击 | 压低前躯、后腿蓄力 | 身体前伸、前爪／头部指向目标 | 朝目标短促推进，不拉伸身体 |
| 受击 | 常态或动作前帧 | 受力侧收、盾面／躯干后撤 | 反方向 1–2px 抖动与短色闪 |

## 6. QA 与来源

每个人物动画资产必须保存：所属角色身份卡、常态身份源、两个端点的独立母图／编辑源、批准的生产渠道或人工工具、生产者与日期、规范化命令或手工步骤、对应视觉层级的接触表、Alpha／色数／尺寸／锚点报告、Importer 或目标运行环境读回。

人工门禁：

1. 遮住名称后，三个状态仍能认出同一单位。
2. 1× 下能区分预备与峰值，且不是整图平移造成的假动作。
3. 4× 下没有抗锯齿、半透明边缘、单像素噪点或部件断裂。
4. 快速来回切换时无身份闪变、身高跳变、武器换手或脚底漂移。
5. 实战中抖动不越出本格可读范围，不遮挡生命／护盾与意图。

## 7. 临时规范退出条件

只有在逐帧生产能跨至少三类角色形态、两个地区／阵营和 A／C 两种视觉层级稳定通过身份一致性、锚点与目标场景阅读 QA 后，才能另立 OCC 正式连续人物动画规范。局部项目不得自行绕过本规范；例外必须写入美术源文件并给出资产级 QA。升级不得自动使现有双状态资产失效，是否扩帧逐个角色、逐项动作决定。
