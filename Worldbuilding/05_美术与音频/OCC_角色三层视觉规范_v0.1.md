# OCC 角色三层视觉规范 v0.1

**状态：执行中。** 每名可命名角色、主角模板、关键 NPC、精英与首领均采用同一角色身份下的三种视觉资产。三者不是替代关系，而是服务不同镜头距离与叙事职责。

## 1. 三层资产定义

| 层级 | 名称 | 主要用途 | 推荐原料画布 | 必须读出的信息 |
| --- | --- | --- | --- | --- |
| A | 战棋形象 | 战斗地图、目标选择、行动条、小头像 | `64×64` 像素静帧 | 阵营、兵种、朝向、主武器/导具、占格 |
| B | 角色立绘形象 | 档案、关系、对话框、装备/人物详情 | 竖构图像素立绘，推荐 `384×576` | 年龄、体态、服装结构、个人装备、身份与人生阶段 |
| C | 演出形象 | 关键对话、抉择、伤病、污染、结局与剧情镜头 | 全身演出单图，推荐 `192×288` | 动作、姿态、眼神、眉眼、嘴部与情绪 |

- A 是战术信息资产，必须以 `64×64` 与 `X=32` / `Y=58` 为准，遵守《OCC 单位像素美术规范 v0.1》。
- B 与 C 是叙事像素资产：保持清晰像素边缘和受控调色板，但不以 64×64 限制面部细节；不得以插画式柔焦、写实渲染或 AI 伪文字替代像素表现。
- 单位群体敌人至少需要 A；命名敌人、关键 NPC、主角与首领需要 A+B；有剧情节点、重要关系或结局的角色需要完整 A+B+C。

## 2. 角色身份合同

每位角色在生成或绘制前建立一张 `Character Identity Card`。A、B、C 必须共享以下不可变字段：

| 身份锚点 | 规则 |
| --- | --- |
| 体态与年龄 | 身高感、肩宽、步态、年龄段与显著伤残在三层保持一致；不得在演出形象中突然年轻化或换体型。 |
| 头部特征 | 发型/发色、肤色、面部轮廓、义眼/疤痕/护目镜等至少保留两项稳定锚点。 |
| 职业轮廓 | 步枪、宽盾、导具线缆、医疗腕具或重甲模块等主特征，在 A 中简化、在 B/C 中展开，不得改变功能身份。 |
| 服装结构 | 外套、护甲、背带、领口、披肩、头盔等层级结构一致；允许按镜头裁切，不允许无理由换装。 |
| 阵营与个人色 | 阵营语义色遵守冷青/氧化红/安全黄橙规则；每名命名角色另保留一个不超过可见面积 10% 的个人识别色或材质。 |
| 以太技术 | 以太只能表现为可维护的导管、线圈、接口、容器或受控器具；不能变成圣光、悬浮符文或无来源魔法。 |

身份卡还需记录：角色 ID、当前人生阶段、阵营、职业、主武器/导具、两条视觉禁忌、A/B/C 的原料与 QA 路径。

## 3. 各层画面合同

### A. 战棋形象

- 近顶视三分之四角，默认面向右下；一格一人，单张独立 `64×64`。
- 1× 优先读取职业与敌我，4× 再读取装备/线缆；不承载可读面部表情。
- 保持硬 alpha、最多 24 色、Point/Clamp、整数缩放。受击、待机以整数像素位移或短时色彩/亮度变化表现。

### B. 角色立绘形象

- 竖构图，以腰部以上或全身三分之二为主，角色占画面高度约 70–85%，预留 UI 裁切安全区。
- 表现服装层级、背包、伤痕、个人装备与人生阶段；背景默认透明或低细节单色/抽象工业块面，不制作可复用地图背景。
- 推荐 32–40 个可见色；可使用比 A 更丰富的明度层次，但仍禁止平滑渐变、空气透视、柔焦和无边界特效。
- 不把 B 当作换装概念图：任何装备、阵营或阶段变化必须有明确剧情/系统来源并更新身份卡。

### C. 演出形象

- C 是**全身剧情演出资产**，而不是面部特写。默认使用固定的竖向演出镜头，单张 `192×288`，角色全身可见并占画面高度约 78–90%；优先采用透明背景，场景由演出层另行叠加。
- 脸部建议达到约 28 像素高，双眼、眉线和嘴部在目标演出尺寸下必须可读；表情由眉形、眼睑、瞳孔、嘴角和头/肩/躯干姿态共同表达，不能只靠浮动符号或文字标签。
- C 以较少像素和较短生产周期支持大量独立动作。基础动作池为：`neutral`、`resolve`、`strain`、`draw`、`aim`、`recoil`、`kneel`、`collapse`；每项均为单独原料，不做 AI 拼板硬切。
- 建议最多 24 个可见色，与战棋形象同级控制；比 A 多出的预算优先给脸部明度、眼神和关键手势，而非服装纹理。保持硬像素边缘，柔边、半透明泪光、景深和写实皮肤渲染均不进入正式资产。
- 角色默认三分之四站姿或动作方向，可按演出需求朝向镜头左/右；仍必须保留身份卡规定的发型、伤痕、服装与主装备锚点。环境元素若不可避免，必须低对比且不遮住脸或关键动作。

## 4. Codex 生成与处理顺序

1. 先写身份卡，先生成/批准 B 或 C 的单张原料以锁定脸部、服装和个人锚点。
2. 再为同一身份卡生成 A；不得要求模型从三层拼板中切出资产。
3. 每层单独生成单图原料，使用纯色绿幕或透明背景处理路线；保留原图、去背中间文件、规范化图、4× QA、调色板和报告。
4. A 使用现有 `64×64` 规范化与 Unity 导入门禁。B/C 的输出尺寸、色表、硬 alpha/背景和 UI 裁切安全区须在各自 QA 报告中记录。
5. 将 A、B、C 并排做一次“身份一致性审查”：至少核对头部锚点、主装备、服装结构、阵营色与人生阶段五项。

## 5. 演出形象 QA 门禁

| 检查项 | 通过条件 |
| --- | --- |
| 脸部可读性 | 全身画面中脸部约 28 像素高；在目标演出尺寸下可明确读到双眼、眉线与嘴形，不能只看发型或轮廓猜情绪。 |
| 动作/表情区分 | `neutral`、`resolve`、`strain` 以及战斗动作在并排审查时无需文字标签即可分辨。 |
| 身份连续性 | 与 A/B 至少共享两条头部特征、一条服装结构和同一主装备/导具语义。 |
| 世界观 | 以太设备有结构和接口；无中世纪法袍、神圣金光、漂浮符文和 AI 伪字。 |
| 像素质量 | 调色板受控、边缘清晰；无软焦、平滑渐变、半透明毛边或非整数缩放。 |
| 归档 | 身份卡、三层原料路径、各层 QA 和一致性审查结论齐全。 |

## 6. 首批执行方式

先以一名可复用的主角模板做完整 A+B+C 样本；通过身份一致性审查后，再扩展到步枪兵、盾卫、术师、突袭者、精英与命名 NPC。群体敌人不会因缺少 B/C 阻塞战棋制作。
