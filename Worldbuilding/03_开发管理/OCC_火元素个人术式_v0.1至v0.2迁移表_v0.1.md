# OCC 火元素个人术式 v0.1 至 v0.2 迁移表 v0.1

## 1. 定位与判定口径

- 源目录：`fire-personal-spells-v0.1`，旧审计 ID `F-P01–F-P50`。
- 目标目录：`fire-personal-spells-v0.2`，新 ID `F-P-M01–M20`、`F-P-U01–U20`、`F-P-R01–R20`。
- `direct`：机械语义等价、可一对一保留拥有关系；目标目录稀有度重标必须公开记录。
- `reselect_same_rarity`：形状、来源、消费、武器路径、数值或合法条件发生实质变化；生成一项按旧稀有度公开重选的持久额度，不自动选择“最近语义”条目。
- `compensation`：无合适替代且不能安全重选时，生成一项按旧 ID 去重的持久退役补偿额度；不得伪装成新术式。
- 最近语义 ID 只用于 UI 解释与审计，不是默认替换目标。

本表结论为 `direct 21`、`reselect_same_rarity 26`、`compensation 3`。三个补偿项同时保证极端满收藏存档仍有足够的新稀有术式供其余十项稀有重选使用。

## 3. 存档迁移合同

1. 当前 `map7` 的恢复代码会使用现行目录过滤拥有 ID。接入 `map8` 时必须先读取旧原始字段、执行本表迁移，再使用 v0.2 目录校验；不得先过滤旧 ID。
2. 保留 `map1–map7` 读取入口。迁移是纯函数、事务式、确定性且幂等；重复加载已升级存档不得重复生成重选或补偿。
3. `direct` 保留拥有关系和原装备槽。稀有度变化写入升级报告，升级后以 v0.2 目录稀有度为准。
4. `reselect_same_rarity` 保存 `{source_old_id, source_rarity, entitlement_id, original_slots}`；候选公开、固定顺序、不可重掷并排除已拥有条目。玩家选定后，原槽仍空时才可恢复装备。
5. `compensation` 保存 `{source_old_id, source_rarity, compensation_id, original_slots}`，当前代码使用稳定 ID `fire-personal-spells-v0.2:compensation:<旧ID>`。精确兑换价值未在本表臆定；产品冻结前必须保持可见、不可丢失。
6. direct 目标已存在时可以合并拥有关系，但升级报告必须写明 `coalesced_existing_target`；两个不同旧重选项不能合并成一个额度。
7. 装备槽中的重选/补偿项在运行时槽位留空，同时在额度中记录全部原槽位。未知 ID 或“装备但未拥有”的孤儿槽位进入显式诊断，不能创造所有权。
8. 历史行动档案保留旧 ID 和旧目录版本，只通过退役表解析显示名；不得改写成新 ID 破坏历史签名。
9. 迁移发生在战后奖励界面时，应在新存档持久化候选 ID 与目录版本；不得换目录后用同一种子生成不同候选并称为同一奖励。
10. 未知或损坏 ID 产生 `unknown_legacy_fire_spell` 隔离记录，不自动补偿。

## 4. 容量与自检门禁

- 表必须严格覆盖 `F-P01–F-P50`，旧 ID 唯一且按数字顺序排列。
- 21 个 direct 目标必须非空且彼此唯一；非 direct 行不得携带 direct 目标，并必须至少列一个最近语义 ID。
- 旧稀有条目共 17 项：4 项 direct 中 R08、R14、R15 占用 3 个新稀有 ID，另 1 项焰击术重标为少见；10 项稀有重选正好对应剩余 10 个新稀有 ID，3 项进入显式补偿。由此满收藏存档不会产生无法兑现的第 11–13 个稀有重选额度。
- 运行时代码源为 `FireSpellSaveMigration`；EditMode 必须验证 50/50 覆盖、21/26/3 分类、direct 唯一、关键非等价项、输入顺序无关、装备槽保留、未知/孤儿诊断与满表容量。
