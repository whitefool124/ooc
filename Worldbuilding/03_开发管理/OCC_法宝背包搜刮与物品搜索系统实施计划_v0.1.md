# OCC 法宝、背包、搜刮与物品搜索系统实施计划 v0.1

## 0. 文档定位

- 状态：BIS-01–BIS-07 首个全链路版本完成；基础背包规格为 6×10，容器搜索采用类《逃离塔科夫》的确定性回合制翻译。
- 归属：战斗规则与物品数据由剧情模式、肉鸽模式共用；剧情模式配置固定获取与长期持有，肉鸽模式配置本局内容池、三选一和局内存档。
- 上位依据：`OCC_游戏策划案.md`、`OCC_魔法技能与道具内容合同_v0.1.md`、`OCC_三层内容池配置_v0.1.md`、`OCC_战棋数值标尺合同_v0.1.md`、`OCC_美术规范_v0.1.md`。
- 本文中的“搜索”主要指类《逃离塔科夫》的未知容器逐项揭示；名称搜索、筛选与排序是背包管理辅助。两者共用物品目录与查询服务，但前者会改变容器的已揭示状态，后者是纯查询。
- 人物造型、穿戴外观和角色背包挂件继续暂停；本文美术范围只含物品、容器、UI 和非人物 VFX。

## 1. 已冻结的产品边界

1. 背包采用格子空间；物品具有宽高，空间与负重是两个独立约束。
2. 基础背包固定为 `6×10`（6 列、10 行、60 格）；坐标以左上角为 `(0,0)`。背包装备和挂载袋后续以独立容器或规则扩展，不改变基础坐标合同。
3. 战斗外可自由整理；战斗内从背包取出、临时换装或换入快捷栏固定消耗 `1 AP`。
4. 战斗 HUD 保留 8 个消耗品快捷槽；其中卷轴与法宝合计最多占 4 格，其余槽可留给药品、护盾电池等普通消耗品。
5. 战利品容器内容初始未知；战斗中靠近后每次“继续搜索”消耗 `1 AP` 并按稳定顺序揭示下一项，物品转移不重复收费；战斗外搜索不消耗时间。普通资源在任务结束后统一结算。
6. 现场取得的关键物品立即进入背包。空间不足时必须当场使用、替换、拆解、丢弃或放弃，不设战利品暂存区。
7. 卷轴固定 1 次；法宝按效果规模为 4/3/2/1 次。每个实例独立记录次数、稳定度与故障，不合并同名实例。
8. 成品法宝不可通过普通充能、维修或换石补回次数；稳定度只存在于明确标记的高风险、远古或可增幅法宝。
9. 所有法宝效果确定性结算，提交前完整预览；不得加入隐藏命中、随机故障或随机反噬。
10. 剧情探索不加入搜索倒计时、随机搜索速度、拖延关门或隐性时间压力。搜索成本只来自公开 AP、位置、背包空间和任务后果。

## 3. 目标数据模型

### 3.1 定义与实例分离

`ItemDefinition` 是只读目录项：

- `id`、显示名、描述、类别、元素、来源、稀有度、构筑标签。
- 格子宽高、基础负重、是否任务物、是否可丢弃/拆解/快捷装备。
- 正式图标路径、预览语义、获取资格和模式可用范围。

`ItemInstance` 是存档实体：

- 稳定 `instance_id`、`definition_id`。
- 剩余次数、最大次数、可选稳定度、公开故障/报废状态。
- 所属容器、格子坐标、快捷槽和获得来源。
- 同名法宝、卷轴永不堆叠；普通材料的堆叠规则另由定义显式填写。

`ArtifactDefinition` 在物品定义之上增加：

- 固定术式效果引用、目标规则、AP/魔力成本、次数档位。
- 正常效果、可选增幅效果、额外次数消耗、越限结果和资格。
- 现代/远古来源、许可/鉴定信息、不可补充规则。

法宝不复制一套战斗结算器；它应复用现有目标预览、效果序列、表现语义和确定性提交管线。

### 3.2 背包与容器

- `InventoryContainerState`：容器 ID、尺寸、负重上限、分类限制、物品放置列表。
- `InventoryPlacement`：实例 ID、左上格坐标和 0°/90° 朝向；旋转后宽高互换，必须经过同一放置校验。
- 必须提供 `CanPlace / Place / Remove / Move / Swap / FindFirstFit / Clone`，所有失败返回稳定错误码。
- 自动放入只用于搜刮和奖励的快捷操作；完整 UI 必须允许玩家选择明确位置。
- 物品搜索与筛选只改变显示集合，不改变格子占用、排序存档或物品状态。

### 3.3 搜刮与搜索

战场容器搜索与搜刮：

- `LootSourceState` 支持一个来源包含多项未知物品、普通结算资源和任务物；保存稳定搜索顺序、已揭示数量与已取走状态。
- 容器初始只显示容量/来源和“未搜索”；每次合法搜索揭示下一项，直到“已搜索”；不使用随机搜索时长。
- 相邻/同格合法性、AP 成本、容量变化、任务物后果在提交前预览。
- 可执行“继续搜索”“拿取选中”“拿取全部已揭示且可放入项”“使用后拿取”“放弃”；每项结果确定，未揭示物品不可取走。
- 无合法搜索目标时不扣 AP；战斗中搜索动作按次扣 1 AP，从已经揭示的容器中转移物品不再逐件收费。
- 普通资源可标为任务后结算，不进入战场背包格。

物品搜索：

- 支持名称/ID 模糊搜索，以及类别、元素、来源、稀有度、尺寸、可用状态、任务物、快捷装备状态筛选。
- 排序键固定为获得顺序、名称、类别、尺寸、负重、剩余次数；同键以 `instance_id` 收束，保证结果稳定。
- 搜索服务为纯查询，不写存档；清空条件后恢复原格子布局。

## 4. 交互与 UI

### 4.1 战斗外背包

- 独立可展开面板，不长期压缩 75% 战场区域。
- 左区为格子背包，中区为选中物品详情，右区为装备/快捷栏和筛选器。
- 先实现点击选取、合法格高亮和确认放置；拖放作为同一命令接口的第二输入方式，不成为唯一操作方式。
- 详情明确显示占格、负重、剩余/最大次数、稳定度、资格、不可充能和丢弃后果。

### 4.2 战斗内背包

- 以暂停命令输入的覆盖层打开，不推进敌方 AI 或行动条。
- 快捷栏内物品直接按自身成本使用；从背包换入快捷栏显示固定 `1 AP` 确认。
- 不允许在一次操作中隐式移动多个物品；空间变化、AP 消耗和被替换物去向必须预览。

### 4.3 搜刮面板

- 战场对象以安全黄橙描边；选择“搜刮”后显示容器内容、拿取后背包占格和失败原因。
- 空间不足时同屏打开紧凑背包整理区，不创建临时仓库。
- 容器状态只显示“未搜索 / 已打开 / 已清空”；锁定、陷阱、损坏等状态必须等具体关卡规则批准后再扩展。

## 5. 存档与模式接入

- 新增版本化库存 DTO，禁止直接序列化运行时对象引用。
- 肉鸽存档建议从 `map6` 升级为 `map7`：保存物品实例、背包放置、快捷栏实例引用、容器领取状态和法宝剩余次数。
- `map6 → map7` 迁移时，把已有普通消耗品和奖励映射为新实例；缺失坐标按稳定 first-fit 放入，无法放入的旧奖励进入迁移报告，不静默丢失。
- 剧情模式使用同一 DTO，但实例持久化范围由剧情存档管理；不继承肉鸽稀有度、三选一和局内清空规则。
- 所有实例 ID 由确定性序列或存档分配器生成；读取后不得因列表顺序改变。

- F-T01 的爆破、燃烧地格和命中反馈先映射现有火焰 VFX 模块；禁止为每件法宝复制一套特效。

合计新增位图上限为 18 张 32×32；状态符号若代码绘制则不计位图。多格物品在 v1 中使用 32×32 图标叠加代码绘制占格轮廓，不制作 `32×宽 × 32×高` 的异形大图。

### 7.3 视觉语义与 QA

- 背景煤灰/铁黑；可执行和选中用冷青；搜刮/战利品用安全黄橙；危险报废和非法操作用锈红；高风险稳定度用暗紫红。
- 物品类别必须靠轮廓区分，不只换颜色。爆破筒应读出工业封装、保险结构与一次性熔断，而不是中世纪圣物。
- 所有图标使用 Point Filter、无压缩、无 mipmap、透明底、整数倍缩放；32×32 原图逐张 QA。
- 图标中文字、数字、次数和稳定度全部由 Unity UI 叠加，不烘焙进像素图。
- 每个新内容图标必须登记 `FormalArtRegistry`、manifest、Importer 审计和运行时可达测试。
- 双分辨率回归至少覆盖：空背包、满包、搜索结果、筛选无结果、战斗换入确认、搜刮空间不足、法宝剩余 1 次和报废状态。

## 8. 测试矩阵

- 数据：重复定义/实例 ID、非法尺寸、越界、重叠、移除、移动、实例独立次数。
- 搜索：中文名/ID、组合筛选、稳定排序、清空条件恢复布局、零结果。
- 搜刮：距离、AP、容量、负重、多项部分成功、拿取全部、任务物、已清空容器。
- 法宝：资格、目标预览、次数扣除时点、取消不扣次数、两次独立实例、耗尽报废、不可充能、稳定度和增幅边界。
- 存档：`map6 → map7`、往返、缺失定义、快捷槽引用、容器领取、剧情/肉鸽隔离。
- UI：键鼠焦点、关闭/返回、战斗不推进、1920×1080/960×540、图标清晰、文本不遮挡。
- 最终门槛：全量 EditMode、Play Mode 垂直切片、Console clean、相关场景 `isDirty=false`。

## 9. 尚不进入实现的产品项

- 异形非矩形占格、嵌套容器、物品堆叠上限和精确负重数值。矩形物品 90° 旋转已进入 v1；挂载袋和收纳容器仍按独立后续批次实现。
- 战利品陷阱、开锁、鉴定小游戏、搜刮耗时条和随机隐藏内容。
- 法宝经济价格、批次故障分类、远古法宝大规模内容池和其余七元素法宝。
- 角色穿戴外观、背包挂件、法宝持握动画和人物资产替换。

这些项目需要独立产品决定或内容批次，不阻塞 F-T01、6×10 背包和基础搜刮垂直切片。
