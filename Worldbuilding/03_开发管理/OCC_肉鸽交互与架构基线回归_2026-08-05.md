## 架构职责与依赖方向

- `CombatPrototypeBootstrap`：跨系统编排和向后兼容的公开命令入口；不拥有持久化细节、地图菜单状态或格子计算规则。
- `RogueliteFlowCoordinator`：肉鸽开发运行、地图运行以及入口/地图菜单状态的唯一所有者。
- `RogueliteSaveGateway`：故事包、短局、首区地图和 UI 偏好的唯一持久化网关；通过 `IRogueliteSaveStore` 隔离 Unity 存储。
- `PlayerPrefsRogueliteSaveStore`：Unity 侧存储适配器，只实现键值读写、删除与 Flush。
- `BattlefieldPresentationAdapter`：75% 战场矩形、格子坐标、点击解析、行动范围、失败原因和只读行动预览的所有者；不提交命令、不改写战斗状态。
- `UiPresentationVersions` 与只读 presentation model：正式 UI 的刷新边界和展示快照，不向玩法层反向写状态。
- `UiVisualEventStream`：协调层到表现层的只读视觉语义通道；表现层不得据此重复结算。
- `FormalUiKit`、主题、布局和动效令牌：共用纯表现基础设施；不读取或修改玩法状态。
- `FormalRogueliteUi`、`FormalCombatHud`、`FormalUiInteractionLayer`、`RogueliteSettlementPresentation`：消费只读模型/事件并调用协调入口。
- `DeveloperConsolePanel`：独立、默认关闭的开发入口；不得承担正式玩家流程。

依赖保持单向：玩法状态与纯合同 → 协调/网关/只读适配 → presentation model 与视觉事件 → 正式表现层。正式表现层不得直接写 `CombatState`、`RogueliteMapRun` 或 PlayerPrefs。

## 后续扩展入口与不可破坏项

- 新流程状态先扩展 `RogueliteFlowCoordinator` 及纯合同测试，再由 Bootstrap 暴露兼容命令。
- 新存档域先扩展 `RogueliteSaveGateway` 和存储接口，稳定键、兼容解析与错误恢复必须有测试。
- 新战斗行动先扩展 `CombatActionPreview`/`BattlefieldPresentationAdapter` 的目标、成本、预期结果与失败原因，再接正式 HUD。
- 新 UI 页面先定义只读 presentation model、版本分区和默认焦点，再使用共用 UI 工厂与动效令牌。
- 不得恢复每帧 JSON/字符串签名轮询、整页无条件重建、正式 UI 直写玩法状态、Bootstrap 直连 PlayerPrefs 或玩家向 IMGUI 菜单。
- 剧情模式探索继续禁止时间压力、敌情倒计时或拖延关门机制。
