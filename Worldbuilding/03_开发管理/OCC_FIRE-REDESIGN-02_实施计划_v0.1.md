# OCC FIRE-REDESIGN-02 实施计划 v0.1

## 1. 目标与边界

把火元素个人术式唯一运行时源从 `fire-personal-spells-v0.1`（F-P01–F-P50）升级为 `fire-personal-spells-v0.2`（F-P-M01–M20、F-P-U01–U20、F-P-R01–R20），完成真实战斗、奖励、装备、行动档案和存档的端到端闭环。旧 ID 不删除审计记录；语义不等价的旧能力必须进入公开重选或明确补偿，禁止静默替换。

本任务属于剧情模式与肉鸽模式共用能力基础设施。剧情模式探索不新增时间压力、倒计时或拖延关门机制。人物正式资产、无关玩法扩展、其余七元素与场景布局修改不在范围内。

## 2. 实施阶段

### A. 合同与迁移冻结

1. 对 F-P01–F-P50 逐项判定 `direct`、`reselect_same_rarity` 或 `compensation`，记录新 ID、理由、稀有度与玩家可见结果。
2. 将运行时版本提升为 `fire-personal-spells-v0.2`，将存档版本提升一档；保留旧版本读取入口和显式升级结果。
3. 冻结五个字段：`combat_affinity`、`delivery_mode`、`weapon_requirement`、`trigger_window`、`consumption_rule`，并定义稳定枚举/错误码。

### B. 目录与确定性执行

1. 以 60 项机械定义替换运行时唯一目录，严格按 M/U/R 各 20 项排序并验证 ID 唯一。
2. 预览在扣费前验证战斗亲和、施放路径、武器要求、触发窗口、消费来源、目标/射程/视线/掩体和友军风险。
3. 执行器只解释数据规则，不按具体 F-P ID 分支；近战路径要求合法近战武器或接触条件，通用附着只强化下一次合法武器攻击，远程施法遵守射线与重掩体。
4. 结果事件公开记录路径、触发、消费、武器与来源，重复状态和相同命令必须得到一致签名。

### C. 获取、装备、UI 与存档

1. 奖励池按 v0.2 稀有度和构筑可用性提供候选，固定种子门禁覆盖 60/60，单局不重复。
2. 装备槽、靶场配置、战斗 HUD、结算奖励与行动档案均从同一目录读取名称、图标、成本、路径和装备状态。
3. 旧存档按逐项表迁移；直迁保留装备关系，重选生成同稀有度公开重选额度，补偿写入明确记录。升级前后重复加载幂等，不静默丢失。

### D. 资产与靶场

1. 优先复用语义一致的正式图标/VFX；新语义不得冒用旧图。确有缺口时制作独立 32×32 正式像素图标并通过尺寸、硬 alpha、有限色、Sprite/Point/Clamp/无 mipmap QA。
2. 独立 `TrainingRange.unity` 注册 60 项，逐项验证可装备、合法预览、至少一个非法预览、真实执行、重复签名一致、内容池可达与存档恢复。
3. 增补聚焦 EditMode 测试；必要时进入 Play Mode 做真实 HUD/配置/棋盘路径验证，不保存场景。

### E. 阶段一验收

使用 Funplay 退出 Play Mode（如有）、请求重编译、等待域重载并检查错误/警告与 Console。运行全量自动化测试和 60/60 靶场审计，完成 1920×1080、960×540 两档回归，确认 `TrainingRange.unity` 与相关场景 clean，更新运行时合同、实施矩阵、验证记录和待办。

### F. 阶段二结构审查与迭代

系统审查 `UnityProject/Assets/Game` 的 Runtime、Editor、Tests、资源注册、存档、UI、战斗结算和 asmdef，以及 `Packages`、相关 `ProjectSettings`。对有代码证据且可安全确认的高/中风险进行最小修复，保留兼容接口或提供显式迁移；每轮修复增加回归测试并重新编译、全量测试、Console 检查，必要时重复 Play Mode 与双分辨率回归。

## 3. 最终门禁

- 目录与真实运行时闭环：60/60。
- 旧存档：50/50 有显式迁移结果；升级幂等，无静默语义替换或丢失。
- 自动化：全量通过，失败 0。
- Unity：编译错误 0、警告 0；Console 无项目错误；相关场景 `isDirty=false`。
- UI：1920×1080 与 960×540 可读，维持左侧地图 75%、右侧 HUD 25%。
- 结构审查：所有可安全确认的高/中风险已修复并有测试证据；需产品决策的事项只记录为真实阻塞。

## 4. 交付物

1. 旧 50→新 60 迁移/重选/补偿表。
2. v0.2 运行时技术合同与 60 项实施矩阵。
3. 代码、测试、正式图标/VFX 注册与 QA 证据。
4. 阶段一全链路验证记录。
5. 全项目结构审查与修复验证文档。
6. 更新后的 `OCC_当前待办.md`。
