# OCC 界面截图采集

在主工程 Unity Editor 的 `OCC > UI Screenshots` 使用：

- `Capture All`：依次采集当前已登记的界面，完成后恢复运行前的场景。
- `Direct/…`：只打开目标界面并截图，适合快速复核一个改动。其余目标可在 Editor 代码中调用 `UiScreenshotCapture.CaptureTarget("目标 ID")`。
- `Stop Current Run`：停止批量采集；已得到的截图保留。

每次运行写入 `Reports/UI/AutoCapture/<UTC 时间>/`。`index.html` 按界面类别列出原图，可记录优先级与具体问题并导出 `review.json`；输入暂存在当前浏览器。`manifest.json` 汇总分类和采集状态，单张 PNG 旁的 JSON 记录目标 ID、实际场景、分辨率和成功/失败。失败目标不生成占位截图。截图取自游戏运行时 Game View；报告不会改写既有图片。推荐使用 1920×1080 Game View，并以 JSON 中的实际尺寸核对。

目标表当前覆盖启动、存档、角色、学院地图与整备、各类节点、服务、战利品、结算、战场、背包、现场搜刮和常见确认弹窗。每次批量报告顶部有全部目标的锚点目录，点击页面名即可跳至截图。地图与结算路线使用固定种子的内存预览进度，不读取或覆盖玩家存档；战斗路线通过固定测试场进入。预览结算只用于检查画面，不能代表完整通关记录或替代正常玩家流程验收。目标 ID 与分类以 `UiScreenshotCapture.cs` 的 `Catalog` 及当次 `manifest.json` 为准；某个目标采集失败时，报告明确显示失败且不会用旧图补位。

本工具覆盖**当前能稳定进入的界面类型**，不把总案中的待实现状态伪装成已完成页面。F71 的保存失败和档案保护使用内存状态预览，不改写真实档案。局部悬浮信息等瞬时状态可按实际评估需要继续登记。新增页面时同时登记目标、直达路径和状态断言，确保后续 `Capture All` 自动覆盖。

采集要求当前场景已保存且没有未保存的场景修改。脚本不保存场景或正式资产；用户可以在报告中逐张记录可读性、遮挡、对齐、点击目标和改进优先级。
