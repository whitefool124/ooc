## 1. 必改项（按优先级）

### C1 格子尺寸 64 → 192（一行决定颗粒）

`Assets/Game/Runtime/Presentation/BattlefieldPresentationAdapter.cs`

```csharp
public const float CellSize = 192f;          // 原 64f：192/32 = 6 倍 = 定案倍率
public const float OverviewCellSize = 192f;  // 原 64f
public const float MinimumCellSize = 192f;   // 原 64f
public const float MaximumCellSize = 384f;   // 原 128f（384/32 = 12 倍）
public const float CellSizeStep = 96f;       // 原 32f（每档 3 原生像素，保持整数倍）
```

**为什么只能取 32 的倍率**：物件宽度 = `sourceWidth × (cellSize / 32)`，
只有 `cellSize` 是 32 的整数倍时，1 个源像素才恰好等于整数个画布单位；否则出现半像素。

### C2 画布整数倍缩放

新增文件（已提交）：`Assets/Game/Runtime/Presentation/PixelPerfectBattlefieldScaler.cs`
—— 编译通过、无警告。挂载点：`CombatFormalVisualAssets.cs` 创建战场画布处（`L142` 附近）：

```csharp
CanvasScaler scaler = canvasObject.AddComponent<CanvasScaler>();
scaler.uiScaleMode = CanvasScaler.ScaleMode.ScaleWithScreenSize;   // 旧写法保留亦可
scaler.referenceResolution = new Vector2(1920, 1080);
scaler.matchWidthOrHeight = .5f;
PixelPerfectBattlefieldScaler.Attach(canvasObject.GetComponent<Canvas>());   // ← 新增
```

组件行为：`scaleFactor = max(1, min(floor(w/1920), floor(h/1080)))`，
即**只允许整数倍**，不能整除时留边，绝不小数缩放；同时打开 `Canvas.pixelPerfect`。

所有战场节点的 `anchoredPosition` 走 `PixelPerfectBattlefieldScaler.Snap(...)`（吸附到 6 的倍数）。

## 2. 验证步骤（改完必须逐条过）

1. **像素一致性**：1920×1080 下整屏截图，量每个 6×6 区块的**块内方差**——应为 0；
   若某片区域方差 > 0，说明该处被小数缩放或未吸附。脚本可复用
   `ArtSource/sephiria_style_study_2026-09-16/tools/analyze_lighting.py` 的 `block_variance`。
2. **接缝检测**：同一行并排 3 张地面瓦片，交界处不得出现 1px 暗/亮线或半像素渗色。
3. **移动测试**：相机/视口平移时像素整格跳动（每帧位移为 6 的整数倍），无游丝抖动。
4. **整数倍档位**：在 1280×720(4×)、1920×1080(6×)、2560×1440(8×)、1600×900(5×) 下分别验；
   1366×768 应留黑边，不得拉伸。
5. **回归**：EditMode 测试全绿（现有 800+ 用例），Console 无新增警告。

## 3. 实机回归实测（2026-09-16，Play Mode，1920×1080）

C1/C2 落地后进 Play Mode 实测（走真实入口，`CombatTestArena` 场景、N01 侧阵对练）：

| 项 | 实测值 | 结论 |
| --- | --- | --- |
| 战场画布 Scalers | `ConstantPixelSize`、`scaleFactor = 1`、`pixelPerfect = true` | 整数倍缩放生效 ✓ |
| `PixelPerfectBattlefieldScaler` | 已挂载；`nativePixelUnits = 6`、`gameplayCellUnits = 192`、`exact = True` | 与定案一致 ✓ |
| 棋盘总尺寸 | 3840×2688 | 12×9 格，每格 **384** |
| 单格 `格子_0_0` | **384×384** | ⚠️ 视图把适配器的 192 **又放大了一倍** |
| 地面 `地面` | RawImage，**64×64** 贴图铺满 384 | 6 屏幕像素/texel ✓ 已达标 |
| 地形物件 | RawImage，**32×32** 贴图铺到 **384** | ⚠️ **12 屏幕像素/texel，是地面的 2 倍** |
| 截图区块分析 | 2×2 区块一致率 100%，6×6 只有约 51–62% | 可见地面实际是 **2 像素/源像素**的格 |

**两条结论**：

1. **用户观察到的"素材本身体积较大"是准确的**：地面 texel = 6 屏幕像素，而 32px 物件被铺进 384px 的格子 = 12 屏幕像素/texel，正好是地面的 2 倍。要让两者同级，物件贴图要么按 64px 出（与地面同源），要么把 `CombatObjectLayerLayout` 的 `cellSize/32` 改成按地面的 64px 基准。
2. **可见地面不是 UI 画的**：URP `UniversalRP.asset` 里 `m_RenderScale: 0.5`（`m_UpscalingFilter: 2`、`m_MSAA: 1`），即相机路径按半分辨率渲染再点采样放大 2 倍——正好解释截图量到的 2 像素栅格。uGUI（Screen Space Overlay）不受 renderScale 影响，所以战场存在**两条并存路径**（相机 SpriteRenderer 层与 uGUI 层）。若战场最终走相机渲染，`m_RenderScale` 必须改回 1；若走 uGUI，则相机那层应当关闭。

**未做**：C4 贴图 Importer（`spriteMeshType: Tight → Full Rect`）；`safeInsetCells` 由 1.5 下调的手感决定；以及上面两条结论对应的实际修复。
