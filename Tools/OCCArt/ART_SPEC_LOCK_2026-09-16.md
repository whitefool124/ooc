## 4. 画风硬规则

1. **不含场景光照**：不烘焙光斑、地面投影、暗角、环境变暗、辉光。**唯一允许的明暗是固定左上的体积明暗**（顶面亮、正面暗）——那是形状语言，不是光照。
2. **像素画语言**：单一均匀方形宏像素格；大块连续明暗；硬边。禁止抗锯齿、渐变、抖色、微纹理、孤立单像素散点。
3. **地面与铺装近乎平色**：主色 ≥45%，铺装目标 75–90%（已通过基准：2–4 色、主色 75.3% / 87.9%、孤立像素 ≤0.5%）。
4. **格边框按新规**：地面方格与不可破坏地形都**自带明显格边框**（1px、本材质暗色、非纯黑）；当前版本**不做材质过渡件**，边框是唯一的格子分隔手段。这条取代早期"不给每格烘焙边框"的规定。
5. **轮廓线**：透明物件与单位保留素材自带的黑色外轮廓；地面不用黑框（用的是本材质暗色边框）。
6. **调色板节制**：中性材质为先；青色只用于活跃以太；锈红只用于敌对或破损；安全黄只用于服务/警示/战利品。

## 5. 世界尺度推导（不用再算）

| 项 | 像素 | 现实 |
| --- | --- | --- |
| 一个玩法格 | 32 | 1.00 m |
| 人形主体区间 | 46–58 | 1.44–1.81 m |
| 火法师（基准人物） | 51 | 1.59 m |
| 寻迹兽主体 | 28 | 0.88 m |
| 地面前立面 | 8 | 25 cm 高差 |
| 一格移动 | 32 | 1 m |
| 盘面 12×9 | 384×288 | 12 × 9 m |
| 视口 7×4 格 | 224×128 | 7 × 4 m |

**为什么是 1 米**：人物 46–58px 是先为剪影独立定的，只有 1 米格下它才等于正常人类身高；1.25 米格会让所有人形变 1.80–2.27 米。两个决定互相印证。
**竖向注意**：侧视人物像素高度 = 真实身高；俯视的地面与墙，画布高度只是高度提示。不可破坏地形按**占满整格 = 阻挡通行与视线**定义，不靠"画得多高"反推。

## 6. 摆放规则 R1–R7

| | 规则 |
| --- | --- |
| R1 | 玩法格 = 32×32 原生像素；**一格一张地面方格**，无子网格、无跨格底图 |
| R2 | 物件底边中心对齐所属格底边；多格物件以左下格为所属格 |
| R3 | 允许上/左/右越格；禁止越过占格底边向南探（**地面前立面例外**，它按定义向南越出 8px） |
| R4 | 层次由后到前：地面 → 地面前立面 → 地面叠加 → 墙体 → 大型结构 → 小道具 → 单位 → 覆盖层 |
| R5 | 层内按底边 y 升序，再按类别（结构 < 道具 < 单位） |
| R6 | 单位 32×64、主体贴画布底边、**脚底偏移 = 0** |
| R7 | 前立面画在下一行地面之后、该行任何墙体/结构/道具/单位之前 |

## 7. 生图流程（六步，不许跳）

1. 用 **Codex 内置 image_gen** 生成独立原料（禁止 EasyCLI、localhost 图像服务、私有 relay）。每次重试用新的独立原料，最多 3 轮，只修被诊断出的那一维。
2. `decode_generated_pixel_grid.py` 解码（地面用 `--ground-window 32x32`）。要求主体宏像素格置信度 ≥1.2；**并要求解码后的设计场 ≤1.4× 交付尺寸**（否则只是大设计的一块碎片）。
3. 出证据：1x / 4x / 6x / 灰阶 / 棋盘格 / 应用接触。
4. 写 manifest（`occ_art_manifest_template_v1.json` → `occ-art-manifest-v1`）。
5. 跑机器校验与对应验收脚本（见下）。
6. **停下等人工复核**，不要自己宣布通过、不要导入 Unity。

提示词直接取 `prompt_templates_2026-09-16.md`；写法原则是**硬规格写死、内容细节交给模型**，数字阈值放在验收环节，不写进提示词。

## 9. 推广到 FORMAL

`FORMAL_CANDIDATE` = 机器 PASS + 人工五维 PASS（剪影/材质/透视/风格/应用）+ 常规五份证据。
`FORMAL` 额外要求（写在 manifest，校验脚本强制）：

1. `evidence.six_x` 六倍证据；
2. `human_review.illumination: PASS`（无烘焙光照）；
3. `unity_import`：`Point` / **`Full Rect`** / 无压缩 / 无 MipMap / `Clamp` / 图集 padding 0、不旋转、不 Tight、Extrude 0 + 稳定 GUID；
4. `unity_import.runtime_lattice`：`verify_runtime_pixel_grid.py` 的通过记录。

**注意**：`Tight` 网格会裁掉四边形、把贴图挤出像素栅格——这是实机像素错位的常见根因。
